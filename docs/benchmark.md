# Benchmark 结果

执行时间：2026-07-30  
环境：Apple M2 Pro，darwin/arm64，Go 1.26.4  
命令：`GOCACHE=/tmp/ugxlsx-gocache go test -bench=. -benchmem ./...`

| 场景 | 有效单元格 | 差异数 | 耗时 | 分配量 | 分配次数 |
|---|---:|---:|---:|---:|---:|
| 读取 + 稀疏索引 | 100,000 | — | 383.11 ms | 307,782,469 B/op | 4,458,311 |
| 对比 + 差异索引（相同） | 100,000 | 0 | 6.83 ms | 2,720 B/op | 20 |
| 对比 + 差异索引（大量差异） | 100,000 | 10,000 | 8.50 ms | 10,559,248 B/op | 40 |
| 对比 + 差异索引（10 sheets） | 1,000,000 | 100 | 137.34 ms | 57,104 B/op | 28 |
| 安全保存 + 两次打开校验 | 100,000 | — | 53.32 ms | 11,353,416 B/op | 18,465 |

`B/op` 是 Go benchmark 给出的每次操作累计分配量，可作为内存成本近似值，不等同于进程峰值 RSS。读取阶段的分配主要来自 excelize 解压/解析 OOXML 和构造稀疏单元格快照；差异归并本身在相同或少量差异时额外分配很小。大量差异场景的内存与差异结果数量线性相关。

基准数据构造位于计时区外。100 万场景是 10 个工作表、每表 10 万有效单元格；算法对两个有序稀疏键序列线性归并，不遍历矩形空白区。
