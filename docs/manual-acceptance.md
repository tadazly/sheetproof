# 手工 GUI 验收

## 现代界面与跨平台显示

1. 在默认窗口和最小窗口附近分别启动，确认顶部“来源 / 差异导航 / 编辑与合并 /
   保存结果”仍可辨认；次要文字可以隐藏，但按钮、状态栏和双网格不得重叠或溢出。
2. 用键盘 Tab 遍历打开、导航、合并、撤销、缩放和保存操作，确认焦点边框清晰；
   disabled 按钮不可触发，鼠标 hover 与按下状态可区分。
3. 确认仓库和普通直接文件模式都显示“原始表格 · 可编辑 / 目标表格 · 只读”的
   紧凑来源卡；Git difftool 模式则两侧均显示“Git 差异快照 · 只读”。加载、
   待选择、已解析、有修改和错误状态同时包含文字或图标，不只依赖颜色。
4. 对比完成后确认结果摘要显示总差异、增加、删除、修改、冲突、当前筛选和选择
   数量；无差异时明确显示“两侧内容一致”。
5. 在 100%、125%、150% 系统缩放或 Retina 显示器检查系统字体、SVG 图标、细边框
   和表格文本清晰；Windows 与 macOS 保留各自系统标题栏、滚动条与原生对话框习惯。
6. 打开错误提示、ID 弹窗、启动加载层、空网格和无搜索结果，确认它们使用一致的
   间距、按钮和状态语言；开启系统“减少动态效果”后不应持续播放装饰动画。
7. macOS 在 Finder、Dock 和应用切换器检查应用图标，Windows 11 在资源管理器、
   任务栏和窗口切换器检查图标；确认不再显示 Wails 默认 “W”，16/32 px 小图标
   仍能辨认深蓝底、双表格和中心合并标记，Retina/高 DPI 下没有锯齿或模糊边缘。

## 仓库模式

准备一个包含同路径 `.xlsx` 不同版本的 Git 仓库，并至少建立一个其他本地
分支、一个远端跟踪引用，以及一个不包含该文件的分支。

1. 无参数启动，确认中央主入口为“打开本地仓库”，并仍可选择两个表格。
2. 点击主入口选择仓库子目录，确认自动定位根目录并显示名称、完整路径与当前分支。
3. 依次打开至少两个仓库，点击仓库信息栏的“切换仓库”，确认弹窗按最近顺序显示
   最多 10 个仓库，当前仓库有明确标记且不可重复选择；点击另一项可直接切换，
   “选择其他仓库”仍打开原生目录选择器。移动其中一个仓库后确认该项显示“路径
   不可用”且不可点击。顶部“打开本地仓库”仍直接打开原生目录选择器，不显示列表。
4. 关闭后重新启动，确认自动恢复最近仓库；移动最近仓库后确认安全回到空状态。
5. 确认目录树文字紧凑；展开/折叠目录，选择多层中文或带空格路径中的
   `.xlsx`。在搜索框分别输入文件名和目录名，确认按完整相对路径筛选且匹配
   目录自动展开；确认独立的清除按钮容易点击，清空后目录树恢复。依次搜索至少
   6 个不同词并逐次结束输入，再聚焦搜索框，确认下方浮层只显示最近 5 条且可点击
   恢复搜索；失焦或按 Enter/Esc 后浮层自动隐藏。切换到另一个仓库确认记录不会
   串库，再切回原仓库确认本地记录恢复。
6. 切换“仓库文件 / 差异表 / 工作表与差异”三个页签。缓存未命中时确认页签
   先显示索引中状态，未经语义确认的候选不会短暂出现；完成后数字等于双方都
   存在且按 `present + raw + formula + type` 确有差异的 `.xlsx` 数量。任一侧
   缺失、仅样式/显示变化或语义完全相同的表都不显示。文件名右侧不预计算单元格
   差异数；打开具体表格后，确认顶部、状态栏和“工作表与差异”页签显示精确数量。
   准备首个工作表无差异、后续工作表有差异的文件，确认打开后自动切到首个有
   差异的工作表，并按“冲突 > 修改 > 删除 > 增加”定位到首个差异；保存后视口
   不应跳回该初始位置。
   再加入一个内容损坏或把旧 `.xls`/OLE 文件误命名为 `.xlsx` 的双方变化候选，
   确认索引提示“已跳过无法解析的 XLSX”并继续显示其他有效差异表；关闭重开后
   直接复用缓存，不再次建立并失败。修复该文件后刷新，确认签名变化会重新检查。
   索引仍在后台建立时回到“仓库文件”并收起任一目录，确认后续轮询和索引完成
   都不会令该目录自动展开。重新触发一个未命中缓存的索引并立即关闭窗口，确认
   应用及时退出，不等待全部候选表格比较完成。
7. 首次打开或没有可恢复项时，确认右侧优先选择当前本地分支的 upstream，未
   配置 upstream 时选择 `origin/<当前分支>` 等同名远端引用。依次切换本地和
   远端分支，确认差异表随引用更新；关闭后用同一分支再次打开，确认恢复所选
   引用并复用已有索引，没有逐表解析等待。删除记录的引用后再次打开，确认按
   上述远端匹配规则回退。
8. 选择不包含同路径文件的分支，确认右侧显示“该分支中不存在此表格”，
   左侧仍显示且合并按钮禁用。
9. 快速连续选择不同文件和分支，确认最终界面和差异表只显示最后一次选择。
   分别直接拖动左侧和右侧表格的横向滚动条，确认当前被拖动窗口自身的行号栏
   从拖动开始到结束都固定在最左侧，不出现先漂移再归位；纵向拖动左右任一侧
   时，当前窗口的列标题也应全程固定。用滚轮连续快速纵向、横向滚动长表，确认
   新显示区域在越过旧区域边界前已开始预取，不出现白屏或等待停滚后才恢复内容；
   分别从左右两侧发起鼠标滚轮和触控板横纵滚动，确认两边从第一帧到停止都保持
   同一位置，没有输入侧领先、另一侧追赶的滞后感；连续滚动期间顶部两行工具栏、
   来源卡和状态栏不得闪烁，按钮也不得因 Region 请求反复切换 disabled 状态。
10. 合并右侧差异；双击左侧单元格原位编辑，分别验证 Enter/失焦提交和 Esc
   取消。确认底部是两行左右值/类型差异栏，保存按钮写明“保存到当前工作区”。
   准备增加、删除、修改行，确认增加值在右侧为绿、删除值在左侧为红、修改
   单元格左红右绿，缺失侧为中性斜纹；准备两边 `id` 相同且其余实际数据列
   全部不同的行，确认整行为橙色冲突。“工作表与差异”中应显示四类行数，
   差异索引提供“增加 / 删除 / 修改 / 冲突”页签。确认默认选择优先级为
   “冲突 > 修改 > 删除 > 增加”，切换页签只显示对应索引，上一处/下一处也
   只在当前分类循环。选中后原语义底色仍保留并叠加蓝色边框；编辑为与右侧
   完全相同后对应差异和计数应消失。额外验证
   右侧为文本 `"123"` 时，左侧输入
   `123` 后不会因被保存成数字而继续标黄。
11. 在增加/删除/修改行右键，确认可“复制单元格到左侧”和“复制整行到左侧”。
    在冲突行右键，确认文案变为覆盖，并提供自动 ID 和指定 ID 两种整行追加。
    多选冲突行时自动项显示连续范围（如 `id:8~10`）；指定 ID 弹窗应逐行输入，
    空值或重复值不能成功。覆盖单元格后确认已相等单元格立即取消红/绿色，未
    处理单元格保留修改色；整行覆盖后右侧显示“已覆盖整行到左侧”。追加后右侧
    显示自动或指定 ID，左侧目标行显示新增绿而不是删除红。逐项撤销，确认每次
    整批操作只占一个撤销步骤且对应处理标记同时消失。另准备左右都无值、但
    一侧带单元格样式的空白列；复制单元格和整行后确认这些空格两侧都不显示
    红/绿色，也不进入差异索引，显式空字符串则仍可在底部类型栏辨认。
12. 修改当前表格后按 `Ctrl/Command+S`，用 `git status --short` 确认工作区
    文件变为 modified，同时确认没有自动 staged/commit，当前分支没有变化。
    保存前先让差异表索引完成；保存后确认没有重新进入全仓索引中状态，只增量
    更新当前表格是否属于差异表。随后不修改任何仓库内容点击刷新，确认直接
    复用原索引，不逐表重新比较。
13. 在左侧存在工具内未保存编辑时切换文件或仓库，分别验证“保存并继续”、
    “不保存并继续”和“取消”。再制造未保存编辑后点击“导出副本”或按
    `Ctrl/Command+Shift+S`，确认目标文件可打开且包含内存编辑，但当前工作区
    文件未被写入、界面仍显示未保存状态，后续 `Ctrl/Command+S` 仍保存到工作区。
14. 拖入有效仓库、仓库子目录、普通目录、文件及多个目录，确认提示和首项处理行为。

CLI 直达流程：

```bash
ugxlsx repo \
  --path "/path/to/repository" \
  --file "config/activity/reward.xlsx" \
  --ref "origin/develop"
```

确认文件或引用无效时显示明确错误，不回退到其他候选。

## 直接文件模式

以下流程覆盖第一轮已经实现的主路径，控制在 15 步内：

1. 执行 `go run ./cmd/gentestdata --dir ./testdata` 生成左右工作簿。
2. 执行 `go run github.com/wailsapp/wails/v2/cmd/wails@v2.10.2 dev`。要验证命令行启动加载，可先执行 `go run github.com/wailsapp/wails/v2/cmd/wails@v2.10.2 build`，再用桌面产物运行 `ugxlsx compare --left testdata/left.xlsx --right testdata/right.xlsx`；确认启动期间出现居中的“正在加载并比较工作簿”提示。
3. 未传入文件时点击“打开左右文件”，依次选择 `testdata/left.xlsx` 和 `testdata/right.xlsx`；确认顶部完整路径、左右角色、工作表状态和总差异数可见，并自动定位到首个有差异的工作表及当前优先分类的第一处。
4. 快速连续点击“下一处”和“上一处”，尤其导航到工作表底部差异；确认左右同时定位，A/B/C…列标题保持在顶部，不出现白屏、大片异常空白或旧区域回跳。
   随后用滚轮连续滚动长表，确认滚动过程中持续预取相邻区域，而不是停下后才显示
   新区域内容；左右两侧分别作为滚轮/触控板输入源时，另一侧应同帧同步。
5. 勾选“差异索引”，点击任意条目；确认显示当前差异序号，并定位到对应坐标。
6. 选择“数据 表”，确认工具栏显示“缩放 100%”；按住 `Ctrl/Command` 滚动
   鼠标滚轮，确认百分比和两侧表格同步变化；点击该按钮确认恢复 100%。拖动
   A/B 列标题分隔线，确认左右列宽同步。
7. 切换到其他工作表再切回“数据 表”，确认该工作簿/工作表的缩放和列宽设置恢复。
8. 点击行号 1，确认整行高亮；Shift 点击其他行号确认扩展选择。在增加、删除
   或修改的单元格上右键，确认出现“复制单元格到左侧 / 复制整行到左侧”。
   对含 `id` 的冲突行重复验证覆盖、自动 ID 追加和逐行指定 ID 追加。
9. 从右侧 A1 拖到 D1，或点击 A1 后 Shift 点击 D1；确认显示选中数量，并且复制按钮只统计选区内的差异单元格。
10. 连续执行两次单格复制，按 `Ctrl/Command+Z` 两次；确认按操作倒序逐步撤销。再执行一次批量复制并撤销，确认整批作为一个步骤撤回。
11. 双击左侧单格，在网格中分别验证文本、数字、公式和清空输入；确认 Enter
    或失焦提交、Esc 取消，底部两行差异栏同步显示左右内容。
12. 修改后按 `Ctrl/Command+S` 并再次用“保存左侧”验证同一流程；确认保存完成
    后撤销仍可用。执行撤销后应重新显示“有未保存修改”，再次保存后结果落盘。
13. 按 `Ctrl/Command+Shift+S`；确认默认文件名沿用左侧文件名，首次目录是系统“下载”目录。取消不应显示错误；另存成功后再次打开，确认默认目录是上次保存位置。
14. 关闭存在未保存修改的窗口，确认出现“保存并继续 / 不保存并继续 / 取消”
    三个按钮；分别确认保存后关闭、丢弃后关闭和取消后留在应用中。Windows 不应
    再显示只有“是 / 否”的系统问题框。
15. 执行 `go run . diff --left testdata/left.xlsx --right testdata/right.xlsx --format json`，确认 JSON 合法且差异数符合操作结果；再用 Excel、LibreOffice 或 WPS 打开保存文件，确认公式、样式、J1:K1 合并区、行高和列宽仍存在。

## UGit 验收

### 自动配置

1. 把 `.app` 或 `.exe` 放到固定目录，先在 UGit 中为 `*.xlsx` 设置一个错误的
   ugxlsx 路径；另为 `*.csv` 保留任意外部工具配置。
2. 启动 ugxlsx，点击顶部“配置 UGit”。确认原生对话框明确说明只替换
   `*.xlsx`，并列出检测到的旧路径；即使当前没有任何 XLSX 工具项，也不得出现
   `HRESULT 0x80070057`。如果系统使用标准对话框回退，正文必须明确“确定”对应
   “配置 UGit”、“取消”对应不修改。点击“取消”后用 `git config --global`
   确认所有配置完全不变。
3. 再次点击并确认。重启 UGit，检查差异工具参数为
   `compare --left "$LOCAL" --right "$REMOTE"`，合并工具参数额外包含
   `--output "$MERGED"`，且 `trustExitCode=false`；原有 CSV 工具仍存在。
4. 不移动应用再次点击，确认提示已经指向当前应用且不会重复写入配置。
5. 关闭应用，把 `.app` 或 `.exe` 移动到另一个固定目录后重开并再次配置；
   确认对话框显示旧路径，完成后全局配置只包含新路径，没有旧路径或重复的
   `*.xlsx` 工具项。
6. macOS 从 `.app` 验证注册路径是
   `Contents/MacOS/ugxlsx`；Win11 验证带空格的安装目录和 `ugxlsx.exe` 路径。
   从 macOS App Translocation 或系统临时目录启动时，应拒绝注册并提示先移动。
7. Windows 确认对话框与成功/错误信息显示 UGit 实际使用的 Git 路径以及
   `file:.../.gitconfig` 等配置来源；同时执行 `where.exe git`，证明即使系统
   `PATH` 指向另一版本，应用仍选择当前 UGit 版本自带的 `cmd\\git.exe`。

### 差异与合并流程

普通命令直接打开真实工作区文件的可写模式：

```bash
ugxlsx compare \
  --left "${LOCAL_FILE}" \
  --right "${REMOTE_FILE}" \
  --left-label "当前分支" \
  --right-label "对比版本"
```

确认 `${LOCAL_FILE}` 是工作区真实文件而不是 Git 临时文件。复制、编辑并
点击“保存左侧”后，使用 `git status` 或 UGit 工作区状态确认该 `.xlsx`
真实发生变化。

UGit 差异工具的 Args 配置为：

```text
compare --left "$LOCAL" --right "$REMOTE"
```

从 UGit 的差异工具入口启动时，确认应用根据 Git difftool 环境自动
进入只读，不要求手工添加 `--readonly-left`。两侧来源卡都显示“Git 差异快照 ·
只读”，可见路径只包含快照文件名而不是 `/var/folders/...` 等临时目录；左侧
网格标题显示“只读”，编辑、复制合并、撤销、另存和保存均不可用。两侧标签应
显示 UGit 当前这次比较的实际分支/引用名，而不是固定的“当前分支 / 对比版本”。

新增/删除文件兼容：

1. 选择两个引用之间只存在于一侧的 `.xlsx`，从 UGit 启动差异工具。
2. 确认窗口正常打开，存在侧的实际单元格按新增或删除显示，而不是闪退并报告
   `unsupported_format (/dev/null)`；整个窗口仍保持只读。
3. 关闭窗口后确认应用及时退出，仓库内没有生成占位文件；占位簿只能位于系统
   临时目录并由进程清理。

合并工具应使用独立参数：

```bash
ugxlsx compare \
  --left "${LOCAL}" \
  --right "${REMOTE}" \
  --output "${MERGED}"
```

准备一个 `.xlsx` 冲突，从 UGit 启动合并工具；确认覆盖/追加和撤销仍可用。
未点击保存直接关闭时 `${MERGED}` 不变；点击保存后结果写入 `${MERGED}`，UGit
可以继续其冲突处理流程。两侧标签应来自 UGit 的实际合并引用；当前合并是
`$LOCAL`/`$REMOTE` 双向语义合并，不使用 `${BASE}`。

### Windows 后台进程和图标

1. 用缓存未命中的真实仓库建立差异表索引；在 Process Explorer 或等价工具中
