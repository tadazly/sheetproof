# 手工 GUI 验收

## 仓库模式

准备一个包含同路径 `.xlsx` 不同版本的 Git 仓库，并至少建立一个其他本地
分支、一个远端跟踪引用，以及一个不包含该文件的分支。

1. 无参数启动，确认中央主入口为“打开本地仓库”，并仍可选择两个表格。
2. 点击主入口选择仓库子目录，确认自动定位根目录并显示名称、完整路径与当前分支。
3. 关闭后重新启动，确认自动恢复最近仓库；移动仓库后确认安全回到空状态。
4. 确认目录树文字紧凑；展开/折叠目录，选择多层中文或带空格路径中的
   `.xlsx`。在搜索框分别输入文件名和目录名，确认按完整相对路径筛选且匹配
   目录自动展开；清空搜索后目录树恢复。
5. 切换“仓库文件 / 差异表 / 工作表与差异”三个页签。缓存未命中时确认页签
   先显示索引中状态，未经语义确认的候选不会短暂出现；完成后数字等于双方都
   存在且按 `present + raw + formula + type` 确有差异的 `.xlsx` 数量。任一侧
   缺失、仅样式/显示变化或语义完全相同的表都不显示。文件名右侧不预计算单元格
   差异数；打开具体表格后，确认顶部、状态栏和“工作表与差异”页签显示精确数量。
   索引仍在后台建立时回到“仓库文件”并收起任一目录，确认后续轮询和索引完成
   都不会令该目录自动展开。重新触发一个未命中缓存的索引并立即关闭窗口，确认
   应用及时退出，不等待全部候选表格比较完成。
6. 首次打开或没有可恢复项时，确认右侧优先选择当前本地分支的 upstream，未
   配置 upstream 时选择 `origin/<当前分支>` 等同名远端引用。依次切换本地和
   远端分支，确认差异表随引用更新；关闭后用同一分支再次打开，确认恢复所选
   引用并复用已有索引，没有逐表解析等待。删除记录的引用后再次打开，确认按
   上述远端匹配规则回退。
7. 选择不包含同路径文件的分支，确认右侧显示“该分支中不存在此表格”，
   左侧仍显示且合并按钮禁用。
8. 快速连续选择不同文件和分支，确认最终界面和差异表只显示最后一次选择。
   分别直接拖动左侧和右侧表格的横向滚动条，确认当前被拖动窗口自身的行号栏
   从拖动开始到结束都固定在最左侧，不出现先漂移再归位；纵向拖动左右任一侧
   时，当前窗口的列标题也应全程固定。
9. 合并右侧差异；双击左侧单元格原位编辑，分别验证 Enter/失焦提交和 Esc
   取消。确认底部是两行左右值/类型差异栏，保存按钮写明“保存到当前工作区”。
   准备增加、删除、修改行，确认增加值在右侧为绿、删除值在左侧为红、修改
   单元格左红右绿，缺失侧为中性斜纹；准备两边 `id` 相同且其余实际数据列
   全部不同的行，确认整行为橙色冲突。“工作表与差异”中应显示四类行数，
   差异索引提供“增加 / 删除 / 修改 / 冲突”页签。确认默认选择优先级为
   “冲突 > 修改 > 删除 > 增加”，切换页签只显示对应索引，上一处/下一处也
   只在当前分类循环。选中后原语义底色仍保留并叠加蓝色边框；编辑为与右侧
   完全相同后对应差异和计数应消失。额外验证
   右侧为文本 `"123"` 时，左侧输入
   `123` 后不会因被保存成数字而继续标黄。
10. 在增加/删除/修改行右键，确认可“复制单元格到左侧”和“复制整行到左侧”。
    在冲突行右键，确认文案变为覆盖，并提供自动 ID 和指定 ID 两种整行追加。
    多选冲突行时自动项显示连续范围（如 `id:8~10`）；指定 ID 弹窗应逐行输入，
    空值或重复值不能成功。覆盖单元格后确认已相等单元格立即取消红/绿色，未
    处理单元格保留修改色；整行覆盖后右侧显示“已覆盖整行到左侧”。追加后右侧
    显示自动或指定 ID，左侧目标行显示新增绿而不是删除红。逐项撤销，确认每次
    整批操作只占一个撤销步骤且对应处理标记同时消失。
11. 用 `git status --short` 确认工作区文件变为 modified，同时确认没有自动
    staged/commit，当前分支没有变化。
12. 在左侧存在工具内未保存编辑时切换文件或仓库，分别验证“保存并继续”、
    “不保存并继续”和“取消”。
13. 拖入有效仓库、仓库子目录、普通目录、文件及多个目录，确认提示和首项处理行为。

CLI 直达流程：

```bash
ugxlsx repo \
  --path "/path/to/repository" \
  --file "config/activity/reward.xlsx" \
  --ref "origin/develop"
```

确认文件或引用无效时显示明确错误，不回退到其他候选。

## 直接文件模式

以下流程覆盖第一轮已经实现的主路径，控制在 15 步内：

1. 执行 `go run ./cmd/gentestdata --dir ./testdata` 生成左右工作簿。
2. 执行 `go run github.com/wailsapp/wails/v2/cmd/wails@v2.10.2 dev`。要验证命令行启动加载，可先执行 `go run github.com/wailsapp/wails/v2/cmd/wails@v2.10.2 build`，再用桌面产物运行 `ugxlsx compare --left testdata/left.xlsx --right testdata/right.xlsx`；确认启动期间出现居中的“正在加载并比较工作簿”提示。
3. 未传入文件时点击“打开左右文件”，依次选择 `testdata/left.xlsx` 和 `testdata/right.xlsx`；确认顶部完整路径、左右角色、工作表状态和总差异数可见。
4. 快速连续点击“下一处”和“上一处”，尤其导航到工作表底部差异；确认左右同时定位，A/B/C…列标题保持在顶部，不出现白屏、大片异常空白或旧区域回跳。
5. 勾选“差异索引”，点击任意条目；确认显示当前差异序号，并定位到对应坐标。
6. 选择“数据 表”，确认工具栏显示“缩放 100%”；按住 `Ctrl/Command` 滚动
   鼠标滚轮，确认百分比和两侧表格同步变化；点击该按钮确认恢复 100%。拖动
   A/B 列标题分隔线，确认左右列宽同步。
7. 切换到其他工作表再切回“数据 表”，确认该工作簿/工作表的缩放和列宽设置恢复。
8. 点击行号 1，确认整行高亮；Shift 点击其他行号确认扩展选择。在增加、删除
   或修改的单元格上右键，确认出现“复制单元格到左侧 / 复制整行到左侧”。
   对含 `id` 的冲突行重复验证覆盖、自动 ID 追加和逐行指定 ID 追加。
9. 从右侧 A1 拖到 D1，或点击 A1 后 Shift 点击 D1；确认显示选中数量，并且复制按钮只统计选区内的差异单元格。
10. 连续执行两次单格复制，按 `Ctrl/Command+Z` 两次；确认按操作倒序逐步撤销。再执行一次批量复制并撤销，确认整批作为一个步骤撤回。
11. 双击左侧单格，在网格中分别验证文本、数字、公式和清空输入；确认 Enter
    或失焦提交、Esc 取消，底部两行差异栏同步显示左右内容。
12. 修改后点击“保存左侧”；确认保存完成后撤销仍可用。执行撤销后应重新显示“有未保存修改”，再次保存后结果落盘。
13. 按 `Ctrl/Command+Shift+S`；确认默认文件名沿用左侧文件名，首次目录是系统“下载”目录。取消不应显示错误；另存成功后再次打开，确认默认目录是上次保存位置。
14. 关闭存在未保存修改的窗口，确认出现“取消 / 丢弃并关闭”提示；选择取消应继续留在应用中。
15. 执行 `go run . diff --left testdata/left.xlsx --right testdata/right.xlsx --format json`，确认 JSON 合法且差异数符合操作结果；再用 Excel、LibreOffice 或 WPS 打开保存文件，确认公式、样式、J1:K1 合并区、行高和列宽仍存在。

## UGit 验收

可写工作区模式：

```bash
ugxlsx compare \
  --left "${LOCAL_FILE}" \
  --right "${REMOTE_FILE}" \
  --left-label "当前分支" \
  --right-label "对比版本"
```

确认 `${LOCAL_FILE}` 是工作区真实文件而不是 Git 临时文件。复制、编辑并
点击“保存左侧”后，使用 `git status` 或 UGit 工作区状态确认该 `.xlsx`
真实发生变化。

只读历史模式在参数末尾增加 `--readonly-left`，此时复制、编辑和保存按钮
应不可用，右侧文件在两种模式下都不得被修改。
