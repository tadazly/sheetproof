# 手工 GUI 验收

## 现代界面与跨平台显示

1. 在默认窗口和最小窗口附近分别启动，确认顶部“来源 / 差异导航 / 编辑与合并 /
   保存结果”仍可辨认；次要文字可以隐藏，但按钮、状态栏和双网格不得重叠或溢出。
2. 用键盘 Tab 遍历打开、导航、合并、撤销、缩放和保存操作，确认焦点边框清晰；
   disabled 按钮不可触发，鼠标 hover 与按下状态可区分。
3. 修改左侧单元格后，按住左侧标题栏的“前后对比”，确认只把左侧内容暂时换成
   打开表格时的原样，且只有打开后改过的单元格变蓝，未改动单元格保持普通底色；
   按钮和标题栏应明确提示正在回看。松开鼠标、Space 或 Enter 立即回到最新结果。
   分别点击左、右网格后按住 Tab，确认得到同样效果，松开 Tab 恢复；在工具栏、
   搜索框或内联编辑框中按 Tab 时仍执行原来的焦点导航或输入逻辑。
4. 确认仓库和普通直接文件模式都显示“原始表格 · 可编辑 / 目标表格 · 只读”的
   紧凑来源卡；Git difftool 模式则两侧均显示“Git 差异快照 · 只读”。加载、
   待选择、已解析、有修改和错误状态同时包含文字或图标，不只依赖颜色。
5. 对比完成后确认结果摘要显示当前工作表的单元格差异、增加、删除、修改、冲突、
   当前行筛选和选择数量；切换到另一张差异类型不同的工作表，确认摘要数字随工作表
   更新而不是继续显示整本工作簿总数。四类指标均可多选且有明确按下态。默认全部不选并显示完整表格；选中一类
   或多类后，左右网格只保留对应差异行，增加/删除的缺失侧仍显示配对空行。按
   `1`、`2`、`3`、`4` 分别切换新增、删除、修改、冲突，按 `5` 在全选四类与全部
   不选之间切换；输入框和原位编辑中按数字不得误触。关闭重开后确认恢复为全部
   不选，不保留上次筛选。当前工作表无差异时明确显示“当前工作表内容一致”。
   在长表第 95 行开启包含该行的筛选，再取消筛选，确认左右两侧回到原始第 95 行
   且该行在视口中的相对位置不跳变；切换到不包含该行的分类时应定位到离第 95 行
   最近的匹配差异行，而不是无条件回到第一条。
6. 在 100%、125%、150% 系统缩放或 Retina 显示器检查系统字体、SVG 图标、细边框
   和表格文本清晰；Windows 与 macOS 保留各自系统标题栏、滚动条与原生对话框习惯。
7. 打开错误提示、ID 弹窗、启动加载层、空网格和无搜索结果，确认它们使用一致的
   间距、按钮和状态语言；开启系统“减少动态效果”后不应持续播放装饰动画。
8. macOS 在 Finder、Dock 和应用切换器检查应用图标，Windows 11 在资源管理器、
   任务栏和窗口切换器检查图标；确认不再显示 Wails 默认 “W”，16/32 px 小图标
   仍能辨认深蓝底、双表格和中心合并标记，Retina/高 DPI 下没有锯齿或模糊边缘。
9. 分别以 English、简体中文和日本語在 1440×900、1600×900 及约 1210×900 的窄窗
   检查工具栏。宽屏显示完整术语；窄窗使用短标签或只保留可辨认图标，品牌、打开、
   差异导航、应用、撤销、缩放、另存、保存和设置之间不得重叠、截断或不合理换行。
10. 点击工具栏“设置”，确认语言切换、UGit 配置和数据清理均在同一模态窗口内。
    切换三种语言后窗口标题、说明、按钮、二次确认和结果信息不得混用其他语言。
    切换为简体中文或日语后关闭应用，不带 `--lang` 重新启动，确认仍恢复刚才选择的语言；
    再用显式 `--lang en` 启动，确认只覆盖本次界面且不改写保存的语言偏好。
    UGit 配置完成、取消或失败的结果必须显示在设置窗口内，不能显示到遮罩后的主界面。
11. 点击“清理缓存”，确认二次弹窗明确说明只删除差异索引缓存，仓库记录、工作簿和
    Git 数据保持不变；确认后最近仓库和已保存对比版本仍存在，需要时重新建立索引。
    点击“清除所有数据”，确认弹窗列出索引、最近仓库、对比版本、搜索记录和视图设置，
    并说明不会修改工作簿或 Git。确认后当前对比保持打开；关闭并重启应用后回到干净
    欢迎页，不自动打开任何仓库。

## 仓库模式

准备一个包含同路径 `.xlsx` 不同版本的 Git 仓库，并至少建立一个其他本地
分支、一个远端跟踪引用，以及一个不包含该文件的分支。

1. 无参数启动，确认中央主入口为“打开本地仓库”，并仍可选择两个表格。把仓库目录
   拖入窗口，确认应用保持在当前页面、不会跳转为空白页，并打开该仓库。
2. 点击主入口选择仓库子目录，确认自动定位根目录并显示名称、完整路径与当前分支。
3. 依次打开至少两个仓库，点击仓库信息栏的“切换仓库”，确认弹窗按最近顺序显示
   最多 10 个仓库，当前仓库有明确标记且不可重复选择；点击另一项可直接切换，
   “选择其他仓库”仍打开原生目录选择器。移动其中一个仓库后确认该项显示“路径
   不可用”且不可点击。顶部“打开本地仓库”显示支持拖入目录的弹窗；点击“手动选择
   文件夹”仍可打开原生目录选择器。分别用两种方式切换仓库，确认未保存确认流程一致。
   选择或拖入一个较大仓库，确认弹窗立即显示“正在打开仓库”和持续旋转的加载标记，完成前
   不能重复提交或关闭弹窗；再选择普通目录或无效仓库，确认错误直接显示在弹窗标题下方，
   长路径和多行错误可以完整滚动查看，而不是出现在弹窗遮罩后面。
4. 关闭后重新启动，确认自动恢复最近仓库；移动最近仓库后确认安全回到空状态。
5. 确认目录树文字紧凑；展开/折叠目录，选择多层中文或带空格路径中的
   `.xlsx`。在搜索框分别输入文件名和目录名，确认按完整相对路径筛选且匹配
   目录自动展开；确认独立的清除按钮容易点击，清空后目录树恢复。依次搜索至少
   6 个不同词并逐次结束输入，再聚焦搜索框，确认下方浮层只显示最近 5 条且可点击
   恢复搜索；失焦或按 Enter/Esc 后浮层自动隐藏。切换到另一个仓库确认记录不会
   串库，再切回原仓库确认本地记录恢复。
6. 切换“仓库文件 / 差异表 / 工作表与差异”三个页签。缓存未命中时确认页签
   先显示索引中状态，未经语义确认的候选不会短暂出现；完成后数字等于双方都
   存在且按 `present + raw + formula + type` 确有差异的 `.xlsx` 数量。任一侧
   缺失、仅样式/显示变化或语义完全相同的表都不显示。文件名右侧不预计算单元格
   差异数；打开具体表格后，确认顶部、状态栏和“工作表与差异”页签显示精确数量。
   准备首个工作表无差异、后续工作表有差异的文件，确认打开后自动切到首个有
   差异的工作表，并按“冲突 > 修改 > 删除 > 增加”定位到首个差异；保存后视口
   不应跳回该初始位置。
   再加入一个内容损坏或把旧 `.xls`/OLE 文件误命名为 `.xlsx` 的双方变化候选，
   确认索引提示“已跳过无法解析的 XLSX”并继续显示其他有效差异表；关闭重开后
   直接复用缓存，不再次建立并失败。修复该文件后刷新，确认签名变化会重新检查。
   索引仍在后台建立时回到“仓库文件”并收起任一目录，确认后续轮询和索引完成
   都不会令该目录自动展开。重新触发一个未命中缓存的索引并立即关闭窗口，确认
   应用及时退出，不等待全部候选表格比较完成。
7. 首次打开或没有可恢复项时，确认右侧优先选择当前本地分支的 upstream，未
   配置 upstream 时选择 `origin/<当前分支>` 等同名远端引用。依次切换本地和
   远端分支，确认差异表随引用更新；关闭后用同一分支再次打开，确认恢复所选
   引用并复用已有索引，没有逐表解析等待。删除记录的引用后再次打开，确认按
   上述远端匹配规则回退。
8. 选择不包含同路径文件的分支，确认右侧显示“该分支中不存在此表格”，
   左侧仍显示且合并按钮禁用。
9. 快速连续选择不同文件和分支，确认最终界面和差异表只显示最后一次选择。
   分别直接拖动左侧和右侧表格的横向滚动条，确认当前被拖动窗口自身的行号栏
   从拖动开始到结束都固定在最左侧，不出现先漂移再归位；纵向拖动左右任一侧
   时，当前窗口的列标题也应全程固定。用滚轮连续快速纵向、横向滚动长表，确认
   新显示区域在越过旧区域边界前已开始预取，不出现白屏或等待停滚后才恢复内容；
   分别从左右两侧发起鼠标滚轮和触控板横纵滚动，确认两边从第一帧到停止都保持
   同一位置，没有输入侧领先、另一侧追赶的滞后感；连续滚动期间顶部两行工具栏、
   来源卡和状态栏不得闪烁，按钮也不得因 Region 请求反复切换 disabled 状态。
   同时确认左右两侧的纵向与横向滚动条轨道都显示差异位置：新增为绿、删除为红、
   修改为黄褐、冲突为橙，位置与对应行列大致对齐；拖动滚动条滑块时标记保持稳定，
   开启差异行筛选后纵向标记按压缩行重新分布。准备至少 10,000 条差异的长表快速
   滚动，确认标记不会导致卡顿、白屏或创建与差异数等量的可见元素。
10. 合并右侧差异；双击左侧单元格原位编辑，分别验证 Enter/失焦提交和 Esc
   取消。左右网格分别聚焦后按 `Ctrl/Command+A`，确认选择当前工作表的全部实际
   单元格而不是选中网页文字；搜索框和原位编辑框中的同一快捷键仍只全选输入文本。
   在可编辑左侧选择单格和多格后分别按 Backspace/Delete，确认内容清空、样式保留，
   多格清空只占一个撤销步骤；在只读左侧或右侧按键不得修改内容。确认底部是两行
   左右值/类型差异栏，保存按钮写明“保存到当前工作区”。
   准备增加、删除、修改行，确认增加值在右侧为绿、删除值在左侧为红、修改
   单元格左红右绿，缺失侧为中性斜纹；准备两边 `id` 相同且其余实际数据列
   全部不同的行，确认整行为橙色冲突。“工作表与差异”中应显示四类行数，
   差异索引提供“增加 / 删除 / 修改 / 冲突”页签。确认默认导航优先级为
   “冲突 > 修改 > 删除 > 增加”，切换索引页签时行筛选同步切换为对应单类，
   上一处/下一处也只在当前分类循环。再从顶部多选两类，确认压缩后的左右行号
   对应各自真实物理行；冲突追加新 ID 后只开冲突筛选，确认左侧显示追加目标行和
   新 ID，右侧仍显示原冲突来源行，且追加目标不会以删除行重复出现。选中后原语义
   底色仍保留并叠加蓝色边框；编辑为与右侧
   完全相同后对应差异和计数应消失。额外验证
   右侧为文本 `"123"` 时，左侧输入
   `123` 后不会因被保存成数字而继续标黄。再准备两份可见文本完全相同、但一份
   使用共享字符串 `t="s"`、另一份使用内联字符串 `t="inlineStr"` 的 XLSX，确认
   这些单元格都显示为普通文本且不进入差异计数；数字与文本等真实类型差异仍应显示。
   再准备双方首行同列为 `id` 的长表，在右侧中间插入一个
   新 ID 并令后续记录物理行整体下移；确认摘要出现“主键对齐”，新 ID 仍显示在前后
   共同记录之间且只统计为 1 个新增行，不能被移到表格最底部，后续相同 ID 不产生连续
   修改。再从左侧中间删除两条记录，确认右侧对应新增行分别保留在各自原邻近位置，尾部
   仍是双方最后一条共同记录。让其中一个既有同 ID 记录仅部分字段变化，
   应为修改；让另一个同 ID 记录的其余实际数据列全部变化，仍应为橙色冲突。点击
   “主键对齐”切换为“按行号”，确认恢复严格物理坐标结果；切回后恢复语义结果。
   完成任一编辑或合并后，对齐按钮应禁用，避免撤销历史中的来源行被重新配对。
   在同一工作表其他位置加入空 ID、重复 ID 和辅助行，确认双方唯一的 `1001` 等记录
   仍按 ID 对齐，而歧义行仅自身保守比较；再把唯一主键表头改为“地图ID”，确认结果
   完全相同。用双方主键列位置不同、全表只有重复 ID，或同时存在“地图ID”和“父级ID”
   两个候选的表复测，确认整表回退原物理行且不会猜错主键。再准备表头为 `code`、
   没有任何 ID 候选的工作表，确认默认没有主键标记；分别在左右任一侧的 A/B/C…列标题
   右键并设为主键，确认双栏对应标题都显示“主键”、对齐与分类立即重算；再次右键可取消。
   产生一次编辑后，菜单应禁用主键切换。双文件、仓库和 UGit/Git 差异入口都应得到相同分类。
11. 在增加/删除/修改行右键，确认可“复制单元格到左侧”和“复制整行到左侧”。
    在冲突行右键，确认文案变为覆盖，并提供自动 ID 和指定 ID 两种整行追加。
    多选差异单元格/行并夹入未改动项，在未改动项上右键，确认菜单仍显示复制或
    覆盖操作，执行时只处理有差异的坐标/行。再同时选择冲突与任一非冲突差异，
    确认菜单不显示批量按钮，而显示“选中的内容中包含冲突，请单独处理冲突部分”。
    多选冲突行时自动项显示连续范围（如 `id:8~10`）；指定 ID 弹窗应逐行输入，
    空值或重复值不能成功。覆盖单元格后确认已相等单元格立即取消红/绿色，未
    处理单元格保留修改色；整行覆盖后右侧显示“已覆盖整行到左侧”。追加后右侧
    显示自动或指定 ID，左侧目标行显示新增绿而不是删除红。逐项撤销，确认每次
    整批操作只占一个撤销步骤且对应处理标记同时消失。另准备左右都无值、但
    一侧带单元格样式的空白列；复制单元格和整行后确认这些空格两侧都不显示
    红/绿色，也不进入差异索引，显式空字符串则仍可在底部类型栏辨认。
    另准备首行为 `id`、但该列实际是“活动id / 关卡名字”等文本属性名的工作表；
    在纯冲突行右键，确认显示“将整行新增到左侧”而不显示自动/指定 ID 文案；
    执行后该行（含文本 ID）原样追加到左侧最后一条数据之后，右侧来源行显示
    “已新增到左侧末尾”，撤销可一次移除。再在增加、删除或修改行右键，确认不
    显示“将整行新增到左侧”，只保留对应的复制单元格/整行操作。
    再准备填充样式编号超出 excelize 0–18 范围的来源单元格，确认复制或追加保留
    值与公式、仅忽略异常填充并给出警告，随后其他右键操作仍可正常执行。
12. 修改当前表格后按 `Ctrl/Command+S`，用 `git status --short` 确认工作区
    文件变为 modified，同时确认没有自动 staged/commit，当前分支没有变化。
    保存前先让差异表索引完成；保存后确认没有重新进入全仓索引中状态，只增量
    更新当前表格是否属于差异表。随后不修改任何仓库内容点击刷新，确认直接
    复用原索引，不逐表重新比较。
13. 在左侧存在工具内未保存编辑时切换文件或仓库，分别验证“保存并继续”、
    “不保存并继续”和“取消”。再制造未保存编辑后点击“导出副本”或按
    `Ctrl/Command+Shift+S`，确认目标文件可打开且包含内存编辑，但当前工作区
    文件未被写入、界面仍显示未保存状态，后续 `Ctrl/Command+S` 仍保存到工作区。
14. 拖入有效仓库、仓库子目录、普通目录、文件及多个目录，确认提示和首项处理行为。

CLI 直达流程：

```bash
sheetproof repo \
  --path "/path/to/repository" \
  --file "config/activity/reward.xlsx" \
  --ref "origin/develop"
```

确认文件或引用无效时显示明确错误，不回退到其他候选。

## 直接文件模式

以下流程覆盖第一轮已经实现的主路径，控制在 15 步内：

1. 执行 `go run ./cmd/gentestdata --dir ./testdata` 生成左右工作簿。
2. Windows 执行 `powershell -ExecutionPolicy Bypass -File scripts/invoke-wails.ps1 dev`；
   macOS/Linux 执行 `go run github.com/wailsapp/wails/v2/cmd/wails@v2.10.2 dev`。
   要验证命令行启动加载，可先用对应入口执行 `build`，再用桌面产物运行
   `SheetProof compare --left testdata/left.xlsx --right testdata/right.xlsx`；确认启动期间
   出现居中的“正在加载并比较工作簿”提示。Windows 离线入口必须先检查已安装 CLI
   和本地模块缓存，不得把 `go run ...@版本` 的元数据联网行为当成本地缺失。
3. 未传入文件时点击“打开左右文件”，依次选择 `testdata/left.xlsx` 和 `testdata/right.xlsx`；确认顶部完整路径、左右角色、工作表状态和总差异数可见，并自动定位到首个有差异的工作表及当前优先分类的第一处。
4. 快速连续点击“下一处”和“上一处”，尤其导航到工作表底部差异；确认左右同时定位，A/B/C…列标题保持在顶部，不出现白屏、大片异常空白或旧区域回跳。
   随后用滚轮连续滚动长表，确认滚动过程中持续预取相邻区域，而不是停下后才显示
   新区域内容；左右两侧分别作为滚轮/触控板输入源时，另一侧应同帧同步。
5. 在结果摘要多选两类差异行，确认左右只显示相同的压缩行集合且滚动同步；清空
   筛选后恢复完整表格。切换“差异索引”分类并点击任意条目，确认行筛选同步为该
   单类、显示当前差异序号并定位到对应坐标。
6. 选择“数据 表”，确认工具栏显示“缩放 100%”；按住 `Ctrl/Command` 滚动
   鼠标滚轮，确认百分比和两侧表格同步变化；点击该按钮确认恢复 100%。拖动
   A/B 列标题分隔线，确认左右列宽同步。
7. 切换到其他工作表再切回“数据 表”，确认该工作簿/工作表的缩放和列宽设置恢复。
8. 点击行号 1，确认整行高亮；Shift 点击其他行号确认扩展选择。在增加、删除
   或修改的单元格上右键，确认出现“复制单元格到左侧 / 复制整行到左侧”。
   对含 `id` 的冲突行重复验证覆盖、自动 ID 追加和逐行指定 ID 追加。
9. 从右侧 A1 拖到 D1，或点击 A1 后 Shift 点击 D1；确认显示选中数量，并且复制按钮只统计选区内的差异单元格。
   将选区扩展到未改动单元格并在该单元格上右键，确认复制操作仍可见且只处理差异
   坐标；将冲突和非冲突差异混在同一选区，确认菜单提示单独处理冲突且不显示批量按钮。
10. 连续执行两次单格复制，按 `Ctrl/Command+Z` 两次；确认按操作倒序逐步撤销。再执行一次批量复制并撤销，确认整批作为一个步骤撤回。
11. 双击左侧单格，在网格中分别验证文本、数字、公式和清空输入；确认 Enter
    或失焦提交、Esc 取消；再用 `Ctrl/Command+A` 全选当前工作表并用
    Backspace/Delete 清空可编辑左侧选区，确认一次撤销恢复整批内容，底部两行
    差异栏同步显示左右内容。右侧网格和双侧只读会话不得响应清空快捷键。
12. 修改后按 `Ctrl/Command+S` 并再次用“保存左侧”验证同一流程；确认保存完成
    后撤销仍可用。执行撤销后应重新显示“有未保存修改”，再次保存后结果落盘。
13. 按 `Ctrl/Command+Shift+S`；确认默认文件名沿用左侧文件名，首次目录是系统“下载”目录。取消不应显示错误；另存成功后再次打开，确认默认目录是上次保存位置。
14. 保持双文件窗口打开，用 Excel、LibreOffice、WPS 或测试工具修改并保存右侧文件；
    确认 SheetProof 显示只读文件已更新的提示并自动重载右侧。随后外部修改可编辑左侧，
    确认弹窗询问是否重载；先制造 SheetProof 内未保存编辑，确认文案明确说明重载会放弃
    这些编辑。分别验证“暂不重载”会保留持续警告和手动重载入口，“重载最新版本”会
    载入磁盘内容并重建差异。用双历史 Git 快照模式重复修改只读左侧来源，确认左侧也
    提示并自动重载，不出现可编辑确认弹窗。
15. 关闭存在未保存修改的窗口，确认出现“保存并继续 / 不保存并继续 / 取消”
    三个按钮；分别确认保存后关闭、丢弃后关闭和取消后留在应用中。Windows 不应
    再显示只有“是 / 否”的系统问题框。
16. 执行 `go run . diff --left testdata/left.xlsx --right testdata/right.xlsx --format json`，确认 JSON 合法且差异数符合操作结果；再用 Excel、LibreOffice 或 WPS 打开保存文件，确认公式、样式、J1:K1 合并区、行高和列宽仍存在。

## UGit 验收

### 自动配置

1. 把 `.app` 或 `.exe` 放到固定目录，先在 UGit 中为 `*.xlsx` 设置一个错误的
   SheetProof 路径；另为 `*.csv` 保留任意外部工具配置。
2. 启动 SheetProof，打开“设置”并点击“配置 UGit”。确认原生对话框明确说明只替换
   `*.xlsx`，并列出检测到的旧路径；即使当前没有任何 XLSX 工具项，也不得出现
   `HRESULT 0x80070057`。如果系统使用标准对话框回退，正文必须明确“确定”对应
   “配置 UGit”、“取消”对应不修改。点击“取消”后用 `git config --global`
   确认所有配置完全不变。
3. 再次点击并确认。重启 UGit，检查 XLSX 差异工具名为
   `SpreadsheetCompare`，参数保留 `compare --left "$LOCAL" --right "$REMOTE"`；
   同后缀还存在供普通 Git 显式选择的 `Custom` difftool 命令；
   确认 UGit 因此显示两行 `*.xlsx` 差异工具，并将其判定为预期的两个协议入口，
   而不是重复配置；
   合并工具参数额外包含 `--base "$BASE" --output "$MERGED"`，且
   `trustExitCode=false`；原有 CSV 工具仍存在。
4. 不移动应用再次点击，确认提示已经指向当前应用且不会重复写入配置；完成信息应
   留在设置窗口中，主界面不得在遮罩后显示同一提示。
5. 关闭应用，把 `.app` 或 `.exe` 移动到另一个固定目录后重开并再次配置；
   确认对话框显示旧路径，完成后全局配置只包含新路径，没有旧路径或重复的
   `*.xlsx` 工具项。
6. macOS 从 `.app` 验证注册路径是
    `Contents/MacOS/SheetProof`；Win11 验证带空格的安装目录和 `SheetProof.exe` 路径。
   从 macOS App Translocation 或系统临时目录启动时，应拒绝注册并提示先移动。
7. Windows 确认对话框与成功/错误信息显示 UGit 实际使用的 Git 路径以及
   `file:.../.gitconfig` 等配置来源；同时执行 `where.exe git`，证明即使系统
   `PATH` 指向另一版本，应用仍选择当前 UGit 版本自带的 `cmd\\git.exe`。

### 差异与合并流程

普通命令直接打开真实工作区文件的可写模式：

```bash
SheetProof compare \
  --left "${LOCAL_FILE}" \
  --right "${REMOTE_FILE}" \
  --left-label "当前分支" \
  --right-label "对比版本"
```

确认 `${LOCAL_FILE}` 是工作区真实文件而不是 Git 临时文件。复制、编辑并
点击“保存左侧”后，使用 `git status` 或 UGit 工作区状态确认该 `.xlsx`
真实发生变化。

UGit 差异工具的 Args 配置为：

```text
compare --left "$LOCAL" --right "$REMOTE"
```

从 UGit 变更列表对真实工作区文件启动“使用差异工具查看”。确认 SheetProof 校验
列表所属 Git 目录后，把真实工作区文件交换到左侧；来源卡显示“当前工作区 · 可编辑 /
Git 版本快照 · 只读”，左侧显示真实仓库路径，右侧只显示快照文件名而不暴露
`.git/ugit/diff`。双击编辑、复制到左侧、撤销和“保存到当前工作区”均可用；保存后
用 `git status --short` 确认只有该 `.xlsx` 变为 modified，没有自动 staged、commit
或分支变化。

再选择两个历史版本启动差异工具，确认两侧来源卡都显示“Git 差异快照 · 只读”，
左侧网格标题显示“只读”，编辑、复制合并、撤销、另存和保存均不可用。把列表复制
到其他目录、伪造工作区路径或令工作区文件不存在时，也必须安全回退为双侧只读，
不能仅凭第二项位于列表目录外就开放保存。

再选择一个内容与工作区相同的历史版本，点击“使用差异工具与工作区对比”。
确认 SheetProof 仍通过 `SpreadsheetCompare-*.txt` 路径列表启动，显示零处差异，
工作区仍位于可编辑左侧；不能因 `git difftool` 判断无字节差异而完全没有窗口。
关闭后确认除 UGit 自己的 Git 元数据缓存外，工作树中没有生成列表文件或导出副本。

新增/删除文件兼容：

1. 选择两个引用之间只存在于一侧的 `.xlsx`，从 UGit 启动差异工具。
2. 确认窗口正常打开，存在侧的实际单元格按新增或删除显示，而不是闪退并报告
   `unsupported_format (/dev/null)`；整个窗口仍保持只读。
3. 关闭窗口后确认应用及时退出，仓库内没有生成占位文件；占位簿只能位于系统
   临时目录并由进程清理。

合并工具应使用独立参数：

```bash
SheetProof compare \
  --left "${LOCAL}" \
  --right "${REMOTE}" \
  --base "${BASE}" \
  --output "${MERGED}"
```

准备一个 `.xlsx` 冲突，从 UGit 启动合并工具；确认覆盖/追加和撤销仍可用。
未点击保存直接关闭时 `${MERGED}` 不变；点击保存后结果写入 `${MERGED}`，UGit
可以继续其冲突处理流程。两侧标签应来自 UGit 的实际合并引用；`${BASE}` 只用于
解释三方语义变化，覆盖/追加来源仍是 `$LOCAL` / `$REMOTE`。

合并语义说明必须是“对比结果”摘要下方的单行紧凑提示。用默认窗口和最小支持
窗口分别确认：提示不能占用双表格的弹性内容轨道，左右表格必须显示可用的数据行，
底部两行差异详情和状态栏必须同时可见。Windows 常规截图可用
`scripts/capture-wails-window.ps1` 一次完成启动、DPI 感知固定尺寸、整窗截图和退出；
官网与 README 的产品截图使用 `cmd/genproductdemo` 生成的游戏配置表示例，避免把
单元测试值当作产品演示内容。整窗概览以 1600×1000 外框启动，并通过
`scripts/capture-wails-window.ps1 -ClientAreaOnly` 直接捕获应用客户区；四周不得
出现桌面、任务栏、其他窗口或系统阴影中的下层内容。功能说明可以使用
`CaptureX/CaptureY/CaptureWidth/CaptureHeight` 直接截取应用内部关键区域，但不能
裁掉该步骤所需的来源、操作或结果信息，也不能补画不存在的控件和状态。

再构造“REMOTE 与 BASE 语义相同，LOCAL 在中间插入一条记录并使后续唯一 ID
整体下移”的文件级冲突。确认界面说明“右侧与共同基线语义一致，没有双方语义
冲突”，右侧同 ID 记录与左侧对齐，后续记录不再全部显示为修改，橙色冲突数为
0。复制对齐后的右侧值应取到对应 ID 的原物理记录；复制右侧逻辑空行应清空左侧，
不能误取右侧下一条物理记录。再构造左右都相对 BASE 修改同一 ID 且其余实际列
全部不同时，才应出现橙色语义冲突行。

### Windows 后台进程和图标

1. 用缓存未命中的真实仓库建立差异表索引；在 Process Explorer 或等价工具中
   记录 SheetProof 的 `git.exe` 子进程。确认候选扫描、`cat-file -e` 和 `show`
   均没有创建可见 `conhost.exe` 窗口，任务栏全程没有“未知应用程序”图标。
2. 索引进行中关闭窗口，确认进程及时退出，且没有遗留 Git、conhost 或导出临时
   文件。自动化进程属性测试不能替代任务栏观察。
3. 在资源管理器、任务栏和 Alt+Tab 检查图标。确认 EXE 资源和运行窗口的大小
   图标均为项目图标，而非默认 W 或未知图标；必要时刷新 Windows 图标缓存后复核。
