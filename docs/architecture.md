# ugxlsx 架构

`ugxlsx` 将 Excel 处理保持在 Go 后端，GUI 与 CLI 复用相同领域逻辑。

## 两种入口模式

直接文件模式仍通过两个 `.xlsx` 路径建立普通 `Session`。仓库模式由
`internal/repository` 先定位 Git 工作区根目录、扫描 `.xlsx` 相对路径并
读取已有引用：

```text
工作区 <root>/<relative.xlsx> ── OpenLeft ── 可写左侧
refs/heads/* 或 refs/remotes/* ── git show ── 系统临时 XLSX ── 只读右侧
```

左侧始终从文件系统读取，因此包含尚未提交的工作区修改。右侧使用完整
`refs/heads/...` 或 `refs/remotes/...` 引用读取，不执行 checkout、
switch 或 fetch。临时文件位于系统临时目录，切换来源和退出时清理。

`Session.ReplaceRight` 只替换只读来源并重新计算差异，不改变左侧内存编辑、
撤销栈和保存目标。`Session.DetachRight` 用于“未选择分支”“分支中没有同
路径文件”等状态；此时左侧仍可显示和编辑，但不制造空工作簿、不计算虚假
差异，也不允许合并。

## 数据流

1. `workbook.Reader` 用 excelize 打开 `.xlsx`，同时计算文件大小、mtime 和 SHA-256。
2. Reader 只遍历工作表的实际行和已存在单元格，形成稀疏 `WorkbookSnapshot`。
3. `diff.Compare` 对两个已经按行列排序的单元格序列做线性归并，并用稀疏行/列
   集合分类增加、删除、修改和冲突行，复杂度保持与有效单元格数量相关。
4. GUI 首次只获取工作簿和工作表摘要；工作表差异分页获取，网格以视口区域获取。
5. 合并或编辑直接修改左侧的 excelize 工作簿对象，并把操作前后状态和会话状态编号压入撤销栈。
6. 保存时先核对左侧文件身份，再写同目录临时文件、`fsync`、重新打开校验、再次核对身份，最后原子替换。

## 包职责

- `internal/workbook`：文件校验、身份、稀疏快照和单元格模型。
- `internal/diff`：工作表集合、顺序和单元格差异。
- `internal/merge`：单元格内容、公式、样式、超链接、批注的捕获和应用。
- `internal/history`：会话级命令栈。
- `internal/storage`：安全保存与保存后验证。
- `internal/preferences`：跨会话保存“另存为”的最后目录、最近仓库、侧栏宽度、
  各仓库的对比引用和精确语义差异文件索引。
- `internal/repository`：Git 根目录发现、XLSX 扫描、分支排序、状态读取、变化候选筛选和引用对象导出。
- `internal/ugit`：UGit `*.xlsx` 外部工具配置检测、跨平台 Git 定位、路径更新和失败回滚。
- `internal/backgroundcmd`：仅对后台 CLI 子进程应用平台进程属性；Windows 使用
  `CREATE_NO_WINDOW`，其他平台为空操作。
- `internal/app`：并发安全的 GUI/CLI 共享会话。
- `internal/cli`：命令解析、结构化输出和退出码。
- `frontend`：Vue 3 仓库导航和双栏视口化网格。

## 并发和内存

首版快照加载按工作表顺序执行，以避免同时解压多个大型 worksheet XML 导致内存峰值失控。差异阶段不构造矩形空白区域；每个有效单元格只在稀疏 map 和排序键序列中出现。GUI 区域 API 最大返回 300×100，当前前端视口请求为 48×20。会话由读写锁保护，保存和编辑不会重入。

前端在滚动停止后按视口请求区域，不把整份工作簿序列化到 WebView。每个区域请求带有递增序号，工作表加载也单独编号；较早的差异索引或区域请求即使晚返回也不会覆盖新工作表，并发请求使用计数器维护忙碌状态。首次打开表格时，前端优先选择首个存在语义差异的工作表，再按“冲突、修改、删除、增加”选择首个非空分类，并直接以该差异坐标计算初始视口；编辑和保存后的摘要刷新仍从当前滚动位置请求区域。列标题和行号栏分别位于滚动容器内的原生 `position: sticky` 图层，由 WebView 在同一次合成滚动中固定，不依赖 `scroll` 事件发生后的 JavaScript 位移补偿。滚动事件只负责同步另一侧和记录实际 `scrollTop/scrollLeft`。差异导航仍会先设置目标，再读取浏览器钳制后的实际滚动值，因此靠近底部或右侧时也不会漂移、回跳或出现大片空白。

启动时后端异步打开命令行传入的两个工作簿，前端轮询 `Bootstrap`。启动全过程显示居中的阻塞式加载提示，完成后才展示可操作状态。

UGit/Git difftool 对新增或删除文件会把缺失侧传为 `/dev/null`，Git for Windows
也可能使用 `NUL`。`internal/cli` 只在直接 `compare` 入口识别这些 null device，
并在系统临时目录创建一个与现存侧工作表同名、但没有单元格数据的有效 `.xlsx`
占位文件。随后仍由普通 `Session`、`diff`、`merge` 和安全保存路径处理；GUI
退出后删除占位目录。此适配不用于仓库模式，因此不改变仓库引用缺失时必须
`DetachRight` 且不制造虚假差异的约定。

Git difftool 同时向工具进程传递 `GIT_DIFF_PATH_COUNTER` 和
`GIT_DIFF_PATH_TOTAL`。`internal/cli` 只有在两者都存在时设置
`Options.GitDiff=true` 并强制 `ReadonlyLeft=true`；单个同名环境变量不会误判。
因此 UGit/Git 差异查看无法编辑、合并或保存临时快照，而普通双文件入口和不带
这些变量的 Git mergetool 仍保持原有可写语义。前端用 `GitDiff` 把两侧标为
“Git 差异快照 · 只读”，只显示快照文件名，不把宿主临时目录作为可写路径呈现。

UGit 5.51.0 会额外注入 `LOCAL_TITLE`、`REMOTE_TITLE` 和 `WORKSPACE_PATH`。
直接 `compare` 在对应 `--left-label` / `--right-label` 为空时逐侧读取前两个
变量作为展示名，显式 CLI 参数优先。标签只进入 `app.Options` 的界面元数据，
不参与路径解析、差异相等判断或保存目标选择；普通 Git 未提供这些 UGit 扩展
变量时继续使用现有文件名回退显示。

顶部“配置 UGit”调用 `internal/ugit`，通过参数数组执行 `git config --global`，
不直接编辑用户的配置文件，也不调用 shell。注册前读取所有符合 UGit 命名规则
的全局 `*.xlsx` 差异/合并项；用户在原生对话框确认后，只清理这些 XLSX 项，
再写入当前可执行文件的差异命令、带 `$MERGED` 的合并命令，以及
`trustExitCode=false`。写入后重新读取并做精确比较；中途失败会用操作前快照
恢复。CSV 等其他后缀不在读取和清理表达式内。

可执行文件路径来自 `os.Executable` 并规范化：macOS 使用 `.app` 内部 Mach-O，
Windows 使用当前 `.exe`。再次配置会把已经移动失效的旧路径替换为新路径。
临时目录、macOS App Translocation 和含单引号的路径会被拒绝，避免写入下次
无法执行的命令。macOS 的 Git 查找优先使用 `PATH`；Windows 先按自然版本顺序
寻找 UGit 的 `app-*\\resources\\app\\git\\cmd\\git.exe`，同版本再回退到
`mingw64\\bin\\git.exe`，之后才使用 `PATH` 和其他常见安装位置。读取配置时
同时取得 `--show-origin`，确认框、成功结果和错误均显示实际 Git 或来源。
UGit 没有公开的工具注册 API，因此外部写入后提示用户重启正在运行的 UGit。

Windows 上 Wails 2.10.2 的 `MessageDialog` 不使用调用方给出的自定义按钮，而会
把问题对话框固定成 Win32 `MB_YESNO` 并返回英文 `Yes` / `No`。根包因此以 build
tag 隔离：Windows 使用 Common Controls v6 `TaskDialogIndirect` 保留业务按钮
文本，其他平台继续使用 Wails 原生实现。关闭窗口和切换会话共用该选择接口；
关闭时“保存并继续”仍调用现有安全保存流程。

Windows 可执行文件继续嵌入多尺寸 ICO。Wails 2.10.2 只设置 `ICON_SMALL`，因此
`OnDomReady` 后由 Windows 专用辅助函数为当前进程顶层窗口补充
`ICON_SMALL`、`ICON_SMALL2` 和 `ICON_BIG`；非 Windows 构建为空操作。

仓库文件或引用切换使用独立的递增请求序号。切换开始时界面先进入明确的
loading/comparing 状态；只有仍属于最新选择的结果可以安装到界面。区域请求
和仓库请求分别编号，避免快速点击文件、分支或差异导航时互相覆盖。

## 前端交互结构

直接文件模式使用“工作表/差异索引 + 左右网格”。仓库模式在同一框架左侧
增加仓库侧栏，并通过页签复用有限宽度：

```text
仓库文件页签：搜索 + XLSX 目录树 + 刷新
差异表页签：双方都存在且按核心语义确有差异的 XLSX 目录树
工作表与差异页签：Sheet 切换 + 差异索引
内容区：当前工作区可写网格 + 对比分支只读网格
底部：当前单元格左右值、类型和差异状态
```

视觉层使用 `frontend/src/style.css` 中的语义设计 Token，集中管理页面、面板、
文字、边框、强调色、四类差异色、控件高度、间距、圆角和阴影。
`frontend/src/components/AppIcon.vue` 提供同一套描边 SVG 图标，
`EmptyState.vue` 复用空状态结构；没有引入第三方 UI 或图标依赖。顶部按
“来源 / 差异导航 / 编辑与合并 / 保存结果”分组，文件来源卡与结果摘要位于
网格之前。响应式规则只改变次要标签的可见性和紧凑度，不改变操作语义、
表格区域请求或左右布局。

操作系统级应用图标使用 `build/appicon.svg` 作为设计源：左右表格表示对比，
红/绿差异块沿用网格的删除/增加语义，中心双向箭头表示检查与合并。
`build/appicon.png` 是 Wails 和 macOS `icns` 的 1024 px 输入，
`build/windows/icon.ico` 则显式包含 16–256 px 多尺寸资源。图标外围保留透明
安全区，不依赖特定平台蒙版或系统字体。运行时大小图标的补充设置只修改 Wails
主窗口的 `WM_SETICON`，不隐藏窗口，也不改变可执行文件资源。

差异表采用两阶段只读索引。第一阶段用 `git diff` 和 `git ls-tree` 取得“工作区
中存在、所选引用中也存在、Git 内容不同”的 `.xlsx` 候选；第二阶段在后台把候选
引用对象导出到系统临时目录，并复用 `internal/app`/`internal/diff`，按
`present + raw + formula + type` 精确过滤。样式或 `display` 单独变化的工作簿
不会进入差异表；后台完成前也不会展示未经语义验证的候选。读取和增量合并使用
同一空白归一化规则：无值、无公式但仅带样式或默认数字类型的单元格视为不存在；
显式存储的空字符串仍是 `present`，所以不会丢失其真实类型。

精确结果以仓库根目录和完整引用保存；引用提交、当前 HEAD，或工作区 XLSX 的
路径、大小、mtime 变化时失效。同一仓库和引用再次打开或手工刷新时先计算轻量
签名，签名未变就直接复用结果。工具内保存当前表格时还会比较“排除当前表格”
后的前后签名；若 HEAD、引用、文件列表和其他表格都未变化，就只按当前 Session
结果增量添加或移除该表并记录新缓存，不重新比较其他表格。无法证明只有当前
表格变化时才退回完整后台索引。文件级精确差异数量仍只在用户打开具体表格后
计算和显示。

后台索引持有独立的可取消 context。窗口关闭先取消该 context，再等待任务清理；
Git 子进程、文件身份读取、工作表行/单元格快照和差异计算边界都会响应取消。
因此关闭不再等待候选工作簿全部比较完成，同时已导出的临时引用文件仍会清理。

前端只在首次接收新仓库时根据文件列表建立目录的默认展开状态。后台索引轮询
更新同一仓库的差异文件与进度时保留当前展开集合，避免异步仓库视图刷新覆盖
用户在“仓库文件”页签中的展开或收起操作。

左侧原位编辑只是 `Controller.EditLeft` 的输入界面，不持有独立工作簿状态。
Enter 或失焦提交，Esc 取消。输入与右侧 `raw` 完全一致时，前端优先沿用右侧
的数字/文本类型；否则按公式前缀和数字语法推断。提交成功后重新获取 Summary、
Differences 和 Region，因此差异高亮仍以 Go 后端结果为准。

Go 后端同时返回单元格状态和行状态。右侧存在、左侧不存在是“增加”，左侧
存在、右侧不存在是“删除”。前端按 Git 双栏语义渲染：增加值在右侧为绿色，
删除值在左侧为红色，修改的旧值/新值分别为左红右绿，缺失侧使用中性斜纹。
若首行存在不区分大小写的 `id` 列、同一物理行两侧 ID 相同且非空，并且其余
实际存在的数据列全部不同，则整行标为橙色“冲突”。空白占位列不参与“全部
不同”的判断。没有 `id` 列时不生成冲突行。

选中态和差异态可叠加：无差异选中项使用蓝色；四类差异保留原底色并叠加蓝色
边框。Summary 按工作表返回四类行计数，Differences 和 Region 返回对应行状态，
所以“工作表与差异”、差异索引和网格使用同一后端分类。差异索引的四个筛选
页签按单元格索引计数，默认顺序为冲突、修改、删除、增加；上一处/下一处只在
当前分类内循环。

## 前后端 API

Wails 暴露的 `Controller` 方法如下：

- `Bootstrap`、`SelectAndOpen`、`OpenFiles`：启动和文件选择。
- `SelectRepository`、`OpenRepository`、`Repository`：打开和读取仓库状态。
- `SelectRepositoryFile`、`SelectRepositoryRef`：加载工作区文件并替换右侧引用。
- `RefreshRepository`、`SetRepositorySidebarWidth`：重新扫描和持久化目录树宽度。
- `Summary`：工作簿、工作表、未保存状态和撤销数量摘要。
- `Region`：读取指定工作表的局部矩形区域。
- `Differences`：分页读取工作表差异索引，单次最多 10,000 条。
- `CopyRightToLeft`、`CopyRightToLeftMany`：单格和批量复制。
- `CopyRowsRightToLeft`：把所选右侧完整行覆盖到左侧相同行。
- `AppendRowsRightToLeft`：把所选右侧完整行追加到左侧，并使用自动或逐行指定 ID。
- `EditLeft`：文本、数字、公式和清空编辑。
- `Undo`：撤销最近一次单格、批量或编辑命令。
- `Save`、`SaveAs`：保存当前目标或打开原生另存为对话框；仓库模式的
  `SaveAs` 通过 `Session.Export` 导出副本，不改变工作区目标与 dirty 状态。

## 合并与撤销

复制前后都通过 `merge.Capture` 捕获单元格值、公式、样式、超链接和批注。批量
复制和整行操作会去重坐标，单次最多 10,000 个；其中任一步失败时会倒序回滚
已应用项目。一次批量、整行覆盖或多行追加形成一个撤销条目。

自动追加 ID 从左侧 `id` 列中的最大整数加一开始，多行按选择顺序连续分配；
指定 ID 弹窗为每个来源行提供一个输入框，并拒绝空值、批内重复或左侧已有 ID。
追加目标从左侧当前最大行之后开始。复制、覆盖、追加、编辑和撤销完成后只重算
受影响工作表的稀疏行分类，不重新读取整个工作簿。

语义差异与“用户如何处理冲突”是两类状态。`Session` 另存
`RowResolution`：单元格覆盖、整行覆盖、自动 ID 追加或指定 ID 追加。Summary
把仍有效的处理标记发给前端；右侧来源行显示处理方式，追加目标行在左侧强制
使用新增色，避免被纯物理行坐标对比显示为删除。处理标记绑定产生它的会话状态
编号，撤销对应操作时一并删除；替换或卸载右侧来源时清空，避免跨分支误标。

撤销条目保存 `BeforeState` 和 `AfterState`。每次修改生成新的状态编号，保存只更新 `savedState`，不会清空历史。因此保存后仍可逐步撤销；撤销到与最近保存不同的状态后，会话重新显示“有未保存修改”，用户再次保存才能把撤销结果写回磁盘。当前没有重做。

## 保存一致性

默认目标始终是加载时的左侧路径（除非给出 `--output` 或在直接文件模式使用
“另存为”）。直接文件模式另存成功后，会话目标切换到新文件，之后“保存左侧”
继续写该新目标；仓库模式则通过同一安全写入器导出副本，不切换 Session 目标、
不清除 dirty，也不改变仓库文件。外部修改检查使用
`size + mtime(ns) + SHA-256`。临时文件与目标位于同一目录，因此最终 rename
不跨文件系统。任何写入或校验失败都会删除临时文件，原目标保持不变。

另存为对话框默认沿用左侧工作簿文件名。首次使用从平台下载目录开始；Windows 使用 Known Folder API，macOS 使用当前用户的 `Downloads`。仅在工作簿安全保存成功后，才把目标父目录写入系统用户配置目录的 `ugxlsx/preferences.json`，后续会话优先从该目录开始。

安全保存顺序：

1. 校验扩展名、目标目录和写权限。
2. 保存当前目标时比较加载后的文件身份，阻止覆盖外部修改。
3. 在目标同目录创建 `.ugxlsx-*.xlsx` 临时文件。
4. 写入、`fsync`、关闭并用 excelize 打开临时文件校验。
5. 再次检查目标身份，避免保存期间发生竞争修改。
6. 保留原权限并原子替换：Unix 使用同目录 rename，Windows 使用 `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`。
7. 同步目录，重新计算身份并再次打开最终文件。

仓库模式把 `Output` 清空，保存目标固定为当前工作区中的所选相对路径。
保存后重新读取 Git 状态以更新 modified 标记，但不会暂存、提交或清理
Git 工作区。merge、rebase、cherry-pick 等操作进行中时，保存前由控制器
显示警告。

## Git 安全边界

所有 Git 子进程都使用 `exec.CommandContext` 参数数组、明确的
`git -C <root>` 和 15 秒超时。文件路径先规范化为仓库内 `.xlsx` 相对路径；
引用必须来自 `for-each-ref` 返回的候选集合。分支下拉框和内部状态保留完整
引用，避免本地与远端同名时发生歧义。仓库功能不调用 shell，也不执行任何
写 Git 状态的命令。用户选中的完整引用按规范化仓库根目录保存在偏好文件中；
下次打开同一仓库时优先恢复。没有记录或记录已失效时先使用当前本地分支的
upstream；没有 upstream 时匹配 `origin/<当前分支>` 等同名远端引用，最后才
回退到当前排序后的第一候选。

## 保真边界

工具以原左侧 OOXML 包为基础做局部 excelize 修改，因此未触碰的常见工作表内容通常保持。回归测试覆盖样式、合并区域、行高、列宽、公式、超链接和批注。excelize 会重写 OOXML 包，未回归验证的高级对象不能承诺二进制或语义完全保真，详见 README 的已知限制。
