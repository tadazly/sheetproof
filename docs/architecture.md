# SheetProof（表鉴）架构

SheetProof 的仓库地址为 `github.com/tadazly/sheetproof`，Go module 使用同一路径。
Excel 处理保持在 Go 后端，GUI 与 CLI 复用相同领域逻辑；仓库迁移不会改变文件格式、
会话模型或保存语义。

## 两种入口模式

直接文件模式仍通过两个 `.xlsx` 路径建立普通 `Session`。仓库模式由
`internal/repository` 先定位 Git 工作区根目录、扫描 `.xlsx` 相对路径并
读取已有引用：

```text
工作区 <root>/<relative.xlsx> ── OpenLeft ── 可写左侧
refs/heads/* 或 refs/remotes/* ── git show ── 系统临时 XLSX ── 只读右侧
```

左侧始终从文件系统读取，因此包含尚未提交的工作区修改。右侧使用完整
`refs/heads/...` 或 `refs/remotes/...` 引用读取，不执行 checkout、
switch 或 fetch。临时文件位于系统临时目录，切换来源和退出时清理。

`Session.ReplaceRight` 只替换只读来源并重新计算差异，不改变左侧内存编辑、
撤销栈和保存目标。`Session.DetachRight` 用于“未选择分支”“分支中没有同
路径文件”等状态；此时左侧仍可显示和编辑，但不制造空工作簿、不计算虚假
差异，也不允许合并。

## 数据流

1. `workbook.Reader` 用 excelize 打开 `.xlsx`，同时计算文件大小、mtime 和 SHA-256。
2. Reader 只遍历工作表的实际行和已存在单元格，形成稀疏 `WorkbookSnapshot`；
   OOXML 共享字符串和内联字符串在此归一为同一语义类型 `string`，避免把序列化
   方式当成内容变化。
3. `diff.Compare` 对两个已经按行列排序的单元格序列做线性归并，并用稀疏行/列
   集合分类增加、删除、修改和冲突行，复杂度保持与有效单元格数量相关。
4. GUI 首次只获取工作簿和工作表摘要；工作表差异分页获取，网格以视口区域获取。
5. 建立会话时保留一份只读的左侧打开快照；合并或编辑只修改当前左侧对象，并把操作前后状态和会话状态编号压入撤销栈。
6. 保存时先核对左侧文件身份，再写同目录临时文件、`fsync`、重新打开校验、再次核对身份，最后原子替换。

## 包职责

- `internal/workbook`：文件校验、身份、稀疏快照和单元格模型。
- `internal/diff`：工作表集合、顺序和单元格差异。
- `internal/merge`：单元格内容、公式、样式、超链接、批注的捕获和应用。
- `internal/history`：会话级命令栈。
- `internal/storage`：安全保存与保存后验证。
- `internal/preferences`：跨会话保存界面语言、“另存为”的最后目录、最近 10 个仓库、
  侧栏宽度、各仓库的对比引用和精确语义差异文件索引；设置窗口可只清除语义索引，
  或清除除当前语言以外的全部已保存应用数据。
  普通 GUI 启动优先恢复保存的语言；只有用户明确传入 `--lang` 时才覆盖本次启动，
  不能把从操作系统探测到的默认语言误判为命令行覆盖。
- `internal/repository`：Git 根目录发现、XLSX 扫描、分支排序、状态读取、变化候选筛选和引用对象导出。
- `internal/ugit`：UGit `*.xlsx` 外部工具配置检测、跨平台 Git 定位、路径更新和失败回滚。
- `internal/backgroundcmd`：仅对后台 CLI 子进程应用平台进程属性；Windows 使用
  `CREATE_NO_WINDOW`，其他平台为空操作。
- `internal/app`：并发安全的 GUI/CLI 共享会话。
- `internal/cli`：命令解析、结构化输出和退出码。
- `frontend`：Vue 3 仓库导航和双栏视口化网格。

## 并发和内存

首版快照加载按工作表顺序执行，以避免同时解压多个大型 worksheet XML 导致内存峰值失控。差异阶段不构造矩形空白区域；每个有效单元格只在稀疏 map 和排序键序列中出现。GUI 区域 API 最大返回 300×100，当前前端视口请求为 48×20。会话由读写锁保护，保存和编辑不会重入。

前端按视口请求区域，不把整份工作簿序列化到 WebView。区域仍固定为 48×20，
但请求起点会在可见范围前后保留缓冲，并按 12 行、4 列的稳定步长移动窗口；
滚动事件以约一帧的间隔合并请求，在当前区域离开视口前预取相邻区域，不再等
滚动停止后才开始加载。每个区域请求带有递增序号，工作表加载也单独编号；较早
的差异索引或区域请求即使晚返回也不会覆盖新工作表。Region 是不改变全局
`busy` 的静默视口请求，避免连续滚动令工具栏反复进入 disabled/busy 状态；编辑、
保存和来源切换等离散操作仍使用计数器维护全局忙碌状态。首次打开表格时，前端
优先选择首个存在语义差异的工作表，再按“冲突、修改、
删除、增加”选择首个非空分类，并直接以该差异坐标计算初始视口；编辑和保存后的
摘要刷新仍从当前滚动位置请求带缓冲的区域。列标题和行号栏分别位于滚动容器内的
原生 `position: sticky` 图层，由 WebView 在同一次合成滚动中固定，不依赖
`scroll` 事件发生后的 JavaScript 位移补偿。滚动事件还负责同步另一侧和记录实际
`scrollTop/scrollLeft`。差异导航仍会先设置目标，再读取浏览器钳制后的实际滚动值，
因此靠近底部或右侧时也不会漂移、回跳或出现大片空白。

行筛选继续遵守视口边界。未选择分类时使用普通 `Region`；选择增加、删除、修改
或冲突的任意组合后，前端调用 `FilteredRegion`，后端从当前 `SheetDiff.Rows` 选择
语义行并压缩成连续显示坐标，每次仍只返回 48×20。每个单元格同时携带显示行、
差异来源行和左右物理行，选择、复制与右键操作使用来源行，左侧原位编辑使用左侧
物理行。增加和删除的缺失侧仍返回同一显示行中的空值，不会只渲染存在的一边。
若右侧行通过追加处理，筛选会把左侧追加目标行与右侧原来源行配对；追加目标不会
再作为另一类物理坐标差异重复出现。筛选只保留在当前前端会话内，应用每次启动
默认全不选并显示完整数据，不写入 WebView `localStorage`、工作簿、Session 或 Git 状态。
筛选切换前记录当前可见或选中单元格对应的来源物理行，以及它相对视口顶部的像素
位置；新筛选仍包含该行时保持原位，不包含时选择最近的匹配来源行。取消筛选则把
压缩显示行映射回同一物理行，因此从第 95 行取消筛选不会跳回第 1 行。

当前工作表查找也保持稀疏和后端权威。`Session` 为左右侧各保存一个小型搜索缓存，
缓存键包含工作表、侧别、查询、大小写/全词/正则选项、规范化行筛选和会话数据代次；
匹配坐标按逻辑行列排序，Wails 只返回数量、当前序号和当前坐标，不序列化完整结果。
未筛选时扫描对齐后的 `comparisonLeft` 或 `right` 的实际单元格；筛选时直接复用
`FilteredRegion` 的语义行与左右物理行映射，再扫描对应原始稀疏快照，因此搜索成本
与有效单元格和文本长度线性相关，而不是与 `MaxRow × MaxCol` 相关。公式搜索
`=公式内容`，其他单元格搜索 `raw`；缺失侧不匹配，显式存在的空字符串仍可由有效
正则命中。Go `regexp` 提供 RE2 语义，Unicode 全词边界由字母、数字和下划线显式判断。

Region 响应只为当前窗口内单元格附加左右匹配布尔标记，当前匹配坐标由搜索摘要叠加，
所以即使超过 10,000 个结果也不会扩大 48×20 响应。编辑、复制、清空、合并、撤销、
外部重载、右侧替换/移除和对齐改变都会递增会话数据代次；保存不改变内存内容，因此
可继续命中缓存。前端两侧分别使用 150ms 防抖、请求序号和独立状态；工作表、来源、
引用或行筛选改变时先使旧结果失效再重跑，较晚返回的旧请求不能安装或触发旧坐标跳转。
查找与 Region 都不进入全局 `busy`，导航命中缓存后为 O(1)，定位仍复用双栏同步滚动
与既有 Region 预取。

每个 Region 单元格同时带回左侧当前值与会话打开时的 `originalLeft`。打开快照是
稀疏深拷贝，只在建立 Session 时生成；后续编辑、合并、撤销和保存都不会改写它。
左侧“前后对比”只在显示层把当前值临时替换为 `originalLeft`，不重新读取磁盘，
也不改变差异、历史、dirty 或保存目标。预览时逐格按 `present + raw + formula + type`
判断是否相对打开快照发生变化：只有改过的格子使用蓝色提示，未改动格子保持普通
底色，避免把当前左右差异配色错误套到旧值上；右侧网格始终保持当前对比来源。

普通滚轮和触控板输入会阻止浏览器只滚动当前容器的默认行为，把连续事件的
`deltaX/deltaY`（包括 line/page 单位及 Shift 横向滚动）累计到下一动画帧，随后
一次性写入左右两个容器，再用输入侧被浏览器钳制后的实际值校正另一侧。这样每帧
最多触发一次双侧位置更新，降低大表高频滚动的布局与合成压力，两侧也不需要等待
输入侧的原生滚动完成后再追赶。程序化同步产生且位置已一致的回声 `scroll` 事件
会直接忽略。直接拖动滚动条、键盘或其他程序化滚动仍由 `scroll` 回退同步。

横向和纵向滚动条轨道使用当前工作表的稀疏差异索引生成位置标记，颜色直接复用
新增、删除、修改和冲突 Token。标记只在工作表、筛选、缩放或列宽提交变化时重建，
不随每个 `scroll` 事件更新；最多聚合为 180 个视觉区间，同一位置由冲突、修改、
删除、新增的优先级决定颜色，因此 10,000 条差异不会生成等量 DOM 或无限增长的
CSS。开启行筛选后，纵向位置使用压缩显示行，横向位置仍按实际列宽映射。

后端 Region 也保持视口成本有界。状态查找不再为每次 48×20 请求遍历并复制当前
工作表的全部差异，而是按已排序的单元格/行索引二分到请求行列范围；FilteredRegion
只为当前请求窗口分配行映射，同时单次预索引冲突追加来源，避免随处理记录数量形成
嵌套扫描。外部文件检查仍在窗口重新可见或获得焦点时立即补查，但应用不可见期间
暂停 2.5 秒轮询，减少后台唤醒且不改变重载确认语义。

启动时后端异步打开命令行传入的两个工作簿，前端轮询 `Bootstrap`。启动全过程显示居中的阻塞式加载提示，完成后才展示可操作状态。

UGit/Git difftool 对新增或删除文件会把缺失侧传为 `/dev/null`，Git for Windows
也可能使用 `NUL`。`internal/cli` 只在直接 `compare` 入口识别这些 null device，
并在系统临时目录创建一个与现存侧工作表同名、但没有单元格数据的有效 `.xlsx`
占位文件。随后仍由普通 `Session`、`diff`、`merge` 和安全保存路径处理；GUI
退出后删除占位目录。此适配不用于仓库模式，因此不改变仓库引用缺失时必须
`DetachRight` 且不制造虚假差异的约定。

Git difftool 同时向工具进程传递 `GIT_DIFF_PATH_COUNTER` 和
`GIT_DIFF_PATH_TOTAL`。`internal/cli` 只有在两者都存在时设置
`Options.GitDiff=true` 并强制 `ReadonlyLeft=true`；单个同名环境变量不会误判。
因此 UGit/Git 差异查看无法编辑、合并或保存临时快照，而普通双文件入口和不带
这些变量的 Git mergetool 仍保持原有可写语义。前端用 `GitDiff` 把两侧标为
“Git 差异快照 · 只读”，只显示快照文件名，不把宿主临时目录作为可写路径呈现。

UGit 5.51 对工具名 `SpreadsheetCompare` 走独立于 `git difftool` 的路径：UGit
自行导出两侧文件，把绝对路径逐行写入 `SpreadsheetCompare-*.txt`，然后直接
执行配置中的程序。`internal/cli` 在普通子命令分派前识别这个单参数协议，严格
要求两个有效 XLSX 路径。UGit 把列表和版本快照放在当前仓库实际 Git 目录的
`ugit/diff`，把真实工作区文件作为列表第二项；CLI 只有在第一项位于该目录、第二项
可规范化到有效 Git 工作区，并且该工作区的 `--absolute-git-dir` 与列表所属目录
完全一致时，才交换两侧并建立 `UGitWorktree` 可写会话。这样左侧继续是唯一写入
目标，右侧版本快照继续只读，编辑、撤销和安全保存无需另写实现，也支持独立 Git
目录的 linked worktree。两个路径都在 `ugit/diff`、工作区文件不存在或任一归属
校验失败时，仍建立 `GitDiff + ReadonlyLeft` 双快照会话。

因为该流程不再依赖 Git 先确认字节差异，“与工作区对比”在所选版本和工作区内容
相同时也能拉起窗口。版本快照和列表仍位于 Git 元数据目录；界面只显示快照文件名，
不会把该目录当成可写目标。工作区保存仍经过文件身份检测和原子替换，不执行任何
Git 状态写操作。

UGit 5.51.0 会额外注入 `LOCAL_TITLE`、`REMOTE_TITLE` 和 `WORKSPACE_PATH`。
直接 `compare` 在对应 `--left-label` / `--right-label` 为空时逐侧读取前两个
变量作为展示名，显式 CLI 参数优先。标签只进入 `app.Options` 的界面元数据，
不参与路径解析、差异相等判断或保存目标选择；普通 Git 未提供这些 UGit 扩展
变量时继续使用现有文件名回退显示。

设置窗口中的“配置 UGit”调用 `internal/ugit`，通过参数数组执行 `git config --global`，
不直接编辑用户的配置文件，也不调用 shell。注册前读取所有符合 UGit 命名规则
的全局 `*.xlsx` 差异/合并项；用户在原生对话框确认后，只清理这些 XLSX 项，
再依次写入工具名为 `SpreadsheetCompare` 的 UGit 直连差异命令、供普通 Git
difftool 显式选择的标准 `Custom` 差异命令、带 `$BASE` / `$MERGED` 的 `Custom`
合并命令，以及 `trustExitCode=false`。直连差异程序路径保留 UGit 直接
`exec` 所需的双引号，以兼容含空格安装目录。写入后重新读取并做精确比较；中途失败会用操作前快照
恢复。CSV 等其他后缀不在读取和清理表达式内。

可执行文件路径来自 `os.Executable` 并规范化：macOS 使用 `.app` 内部 Mach-O，
Windows 使用当前 `.exe`。再次配置会把已经移动失效的旧路径替换为新路径。
临时目录、macOS App Translocation 和含单引号的路径会被拒绝，避免写入下次
无法执行的命令。macOS 的 Git 查找优先使用 `PATH`；Windows 先按自然版本顺序
寻找 UGit 的 `app-*\\resources\\app\\git\\cmd\\git.exe`，同版本再回退到
`mingw64\\bin\\git.exe`，之后才使用 `PATH` 和其他常见安装位置。读取配置时
同时取得 `--show-origin`，确认框、成功结果和错误均显示实际 Git 或来源。
UGit 没有公开的工具注册 API，因此外部写入后提示用户重启正在运行的 UGit。
配置完成、取消或失败后的信息显示在设置窗口内，不写到被模态层遮住的主界面提示条。

同一设置窗口提供两级本地数据清理。“清理缓存”只清除
`RepositoryIndexes`，保留最近仓库、对比引用和其他偏好；“清除所有数据”还清除
最近仓库、对比引用、另存目录、侧栏宽度以及 WebView 中的仓库搜索记录和工作簿
视图设置，但保留当前语言，且不关闭当前内存会话、不删除工作簿、不修改仓库或 Git。
两项操作都由前端三语二次确认；清理时取消正在运行的差异索引并递增代次，旧任务不得
在确认完成后重新写回缓存。下次启动不再自动打开任何仓库。

Windows 上 Wails 2.10.2 的 `MessageDialog` 不使用调用方给出的自定义按钮，而会
把问题对话框固定成 Win32 `MB_YESNO` 并返回英文 `Yes` / `No`。根包因此以 build
tag 隔离：Windows 使用 Common Controls v6 `TaskDialogIndirect` 保留业务按钮
文本，其他平台继续使用 Wails 原生实现。关闭窗口和切换会话共用该选择接口；
关闭时“保存并继续”仍调用现有安全保存流程。Windows 辅助函数在整个
`TaskDialogIndirect` 生命周期锁定同一 OS 线程，以 STA 模式初始化 COM，并在返回后
成对反初始化；否则 Wails 绑定回调线程首次显示对话框会返回
`E_INVALIDARG (0x80070057)`。owner 只有在属于当前进程且可见、启用时才传入；
TaskDialog 失败时先去掉 owner 重试，再回退到标准 `MessageBoxW`。回退层按按钮
角色把 `IDOK/IDCANCEL` 或 `IDYES/IDNO/IDCANCEL` 映射回原业务选项，并在正文中
显示映射说明，所以对话框实现差异不会跳过后续 UGit 配置或保存选择。

Windows 可执行文件继续嵌入多尺寸 ICO。Wails 2.10.2 只设置 `ICON_SMALL`，因此
`OnDomReady` 后由 Windows 专用辅助函数为当前进程顶层窗口补充
`ICON_SMALL`、`ICON_SMALL2` 和 `ICON_BIG`；非 Windows 构建为空操作。

仓库文件或引用切换使用独立的递增请求序号。切换开始时界面先进入明确的
loading/comparing 状态；只有仍属于最新选择的结果可以安装到界面。区域请求
和仓库请求分别编号，避免快速点击文件、分支或差异导航时互相覆盖。

欢迎页的“打开本地仓库”直接打开原生目录选择器；进入主界面后，顶部同名入口先显示
同时支持目录拖入和手动选择的应用内弹窗。Wails 文件拖放保持启用，前端在 Vue 挂载前
注册 Wails 的 DOM 拖放处理器，由它阻止 WebView 默认导航并把原生路径交给 Go 侧监听器；
Windows 不能启用 `DisableWebViewDrop`，因为 WebView2 会同时拒绝外部文件拖入。仓库信息栏的
目录拖入处理在后台打开仓库前先发出 `repository-drop-started`，使应用内导入弹窗立即进入
阻塞式加载状态；完成事件只在仓库结果被前端接收后关闭弹窗，失败事件则保留弹窗并在标题
下方显示可滚动、可换行的错误信息。手动目录选择复用同一弹窗状态，不把错误或进度放到遮罩
后面的全局提示条中。
“切换仓库”先读取偏好中的最近 10 个仓库并显示前端弹窗；当前仓库不可重复选择，
目录已移动或删除的记录显示为不可用。选择有效记录后仍调用 `OpenRepository`，
因此复用相同的未保存确认、仓库校验、会话替换和异步索引流程；“选择其他仓库”
再进入原有目录选择器。

## 前端交互结构

直接文件模式使用“工作表/差异索引 + 左右网格”。仓库模式在同一框架左侧
增加仓库侧栏，并通过页签复用有限宽度：

```text
仓库文件页签：搜索 + XLSX 目录树 + 刷新
差异表页签：双方都存在且按核心语义确有差异的 XLSX 目录树
工作表与差异页签：Sheet 切换 + 差异索引
内容区：当前工作区可写网格 + 对比分支只读网格
底部：当前单元格左右值、类型和差异状态
```

视觉层使用 `frontend/src/style.css` 中的语义设计 Token，集中管理页面、面板、
文字、边框、强调色、四类差异色、控件高度、间距、圆角和阴影。
`frontend/src/components/AppIcon.vue` 提供同一套描边 SVG 图标，
`EmptyState.vue` 复用空状态结构；没有引入第三方 UI 或图标依赖。顶部按
“来源 / 差异导航 / 编辑与合并 / 保存结果”分组，文件来源卡与结果摘要位于
网格之前。响应式规则只改变次要标签的可见性和紧凑度，不改变操作语义、
表格区域请求或左右布局。工具栏低于 1280px 时使用三语短标签并收起次要按钮文字；
语言和 UGit 配置统一放在设置窗口。设置左侧是独立的帮助入口：它在欢迎页和会话页都可用，
从前端构建时导入的 `frontend/package.json` 显示版本，并按当前界面语言调用 Wails
`BrowserOpenURL` 打开官网使用说明，绝不让应用 WebView 离开本地界面。帮助模态自身
拦截背景快捷键、约束 Tab 焦点并在关闭后恢复到帮助按钮；快捷键清单以单个结构化条目表
和 i18n key 渲染，确保三语和实际实现共用同一份操作范围。

操作系统级应用图标使用 `build/appicon.svg` 作为设计源：左右表格表示对比，
红/绿差异块沿用网格的删除/增加语义，中心双向箭头表示检查与合并。
`build/appicon.png` 是 Wails 和 macOS `icns` 的 1024 px 输入，
`build/windows/icon.ico` 则显式包含 16–256 px 多尺寸资源。图标外围保留透明
安全区，不依赖特定平台蒙版或系统字体。运行时大小图标的补充设置只修改 Wails
主窗口的 `WM_SETICON`，不隐藏窗口，也不改变可执行文件资源。

差异表采用两阶段只读索引。第一阶段用 `git diff` 和 `git ls-tree` 取得“工作区
中存在、所选引用中也存在、Git 内容不同”的 `.xlsx` 候选；第二阶段在后台把候选
引用对象导出到系统临时目录，并复用 `internal/app`/`internal/diff`，按
`present + raw + formula + type` 精确过滤。样式或 `display` 单独变化的工作簿
不会进入差异表；后台完成前也不会展示未经语义验证的候选。读取和增量合并使用
同一空白归一化规则：无值、无公式但仅带样式或默认数字类型的单元格视为不存在；
显式存储的空字符串仍是 `present`，所以不会丢失其真实类型。这里的 `type` 是
归一后的语义类型：共享字符串表的 `t="s"` 与单元格内联的 `t="inlineStr"` 都是
`string`；数字、文本、公式、布尔值和日期之间的差异仍保留。

精确结果以仓库根目录和完整引用保存；引用提交、当前 HEAD，或工作区 XLSX 的
路径、大小、mtime 变化时失效。同一仓库和引用再次打开或手工刷新时先计算轻量
签名，签名未变就直接复用结果。工具内保存当前表格时还会比较“排除当前表格”
后的前后签名；若 HEAD、引用、文件列表和其他表格都未变化，就只按当前 Session
结果增量添加或移除该表并记录新缓存，不重新比较其他表格。无法证明只有当前
表格变化时才退回完整后台索引。文件级精确差异数量仍只在用户打开具体表格后
计算和显示。

后台索引持有独立的可取消 context。窗口关闭先取消该 context，再等待任务清理；
Git 子进程、文件身份读取、工作表行/单元格快照和差异计算边界都会响应取消。
因此关闭不再等待候选工作簿全部比较完成，同时已导出的临时引用文件仍会清理。

逐表语义过滤把 `corrupt_workbook`、`unsupported_format` 和 `no_worksheets` 视为
候选文件级问题：跳过该路径、继续比较其他候选，并在签名复核成功后缓存有效结果。
文件大小或 mtime 变化会改变签名，使修复后的文件重新进入检查；Git 读取、权限、
取消和仓库并发变化等错误仍会终止本轮索引，不能被误缓存。若扩展名为 `.xlsx`
但文件头是 OLE Compound，Reader 会明确报告不支持的旧二进制或加密复合格式，
而不是笼统标为损坏工作簿。

前端只在首次接收新仓库时根据文件列表建立目录的默认展开状态。后台索引轮询
更新同一仓库的差异文件与进度时保留当前展开集合，避免异步仓库视图刷新覆盖
用户在“仓库文件”页签中的展开或收起操作。

仓库搜索使用 WebView 的 `localStorage` 按规范化仓库根路径保存最近 5 条非空搜索词。
搜索框聚焦时以浮层显示当前仓库自己的记录，失焦或按 Enter/Esc 后记录当前搜索并
收起；切换仓库会清空当前筛选并加载新仓库的独立记录。清除操作使用应用内按钮，
不依赖 WebView 原生 `type=search` 的小型取消控件。

左侧原位编辑只是 `Controller.EditLeft` 的输入界面，不持有独立工作簿状态。
Enter 或失焦提交，Esc 取消。输入与右侧 `raw` 完全一致时，前端优先沿用右侧
的数字/文本类型；否则按公式前缀和数字语法推断。提交成功后重新获取 Summary、
Differences 和 Region，因此差异高亮仍以 Go 后端结果为准。若输入仍是进入编辑时的
原始表达（公式使用 `=公式`，普通值使用 `raw`），前端直接结束编辑，不进入全局忙碌
状态，也不触发这些刷新。后端在应用编辑前再次按核心语义防御 no-op；同一公式忽略
计算缓存 `raw` 的差别，显式空字符串和不存在单元格仍由 `present` 区分。

左右任一网格聚焦时，`Ctrl/Command+A` 把当前显示工作表的实际数据范围设为选区；
行筛选开启时只选择压缩视图中的行。只有可编辑左侧网格接收 Backspace/Delete 清空，
搜索框、原位编辑框和只读右侧保留各自原生键盘行为。清空请求只传矩形边界或筛选后的
左侧物理行映射，后端从稀疏左侧快照中选择实际存在的单元格，不要求前端加载整张工作表。
多格清空保留样式、批注和超链接，并作为一个撤销步骤记录。

左侧标题栏的“前后对比”采用按住态：鼠标、Space 或 Enter 松开后立即恢复最新
左侧值。左右任一网格被点击后会获得不进入常规 Tab 顺序的程序化焦点；仅此时
按住 Tab 才进入预览，`keyup`、窗口失焦或切换工作表都会恢复最新状态。工具栏、
搜索框和内联编辑框继续使用原有 Tab 导航/输入行为。

Go 后端同时返回单元格状态和行状态。右侧存在、左侧不存在是“增加”，左侧
存在、右侧不存在是“删除”。前端按 Git 双栏语义渲染：增加值在右侧为绿色，
删除值在左侧为红色，修改的旧值/新值分别为左红右绿，缺失侧使用中性斜纹。
若首行存在共享的记录主键列、同一对齐记录两侧主键相同且非空，并且其余
实际存在的数据列全部不同，则整行标为橙色“冲突”。空白占位列不参与“全部
不同”的判断。没有可靠主键列时不生成冲突行。

普通双文件、仓库、UGit/Git difftool 和 CLI `diff` 默认使用安全的唯一主键对齐。
主键列由 `internal/workbook.RecordKeyColumn` 统一解析：双方首行同列同名，精确 `id`
优先；否则仅当全表只有一个以 `ID` 结尾的同名候选（例如“地图ID”）时采用。多个
`mapID` / `parentID` 类候选属于歧义，整表保守回退物理行，不按唯一度猜测。用户也可
右键双栏任一 A/B/C…列标题，在产生撤销历史前显式设置或取消当前工作表的主键列；
显式设置复用同一后端分类、冲突、复制和撤销路径，不是前端显示覆盖。

对在双方各出现一次的非空主键，后端构造一条统一逻辑记录序列，并同时保存“逻辑行 →
左侧物理行”和“逻辑行 → 右侧物理行”映射。同表其他空白主键、重复主键或辅助行只对
自身保守使用物理行，不能否决整张表的可靠记录对齐。仅一侧存在的记录插入到其下一条
共同主键记录之前；没有后续共同锚点时才进入尾部。因此中间新增或删除仍保留原有邻近
位置，只生成真实的新增/删除，不会被统一移到视图末尾，也不会把后续共同记录放大为
连续修改。只有缺少可识别的共享主键表头，或整张表完全没有可可靠识别的唯一主键时，
工作表才整表回退物理坐标。摘要按当前工作表显示对齐方式；在产生任何撤销历史前，用户
可切换“主键对齐 / 按行号”，以便对行顺序本身有业务意义的工作表执行严格物理坐标比较。

Git mergetool 入口额外传入 `$BASE` 并设置 `Options.GitMerge`。它继续允许可靠的唯一
主键记录与同表中的空白/重复主键记录混合：唯一主键对齐，无法可靠识别的记录按坐标
回退。差异、Region、右侧复制和追加始终共享同一物理来源映射，右侧逻辑空行不会
误读原物理行。对齐和行分类复用同一个主键列解析结果；冲突谓词没有因对齐方式改变：只有已经配对的同一非空主键记录在其余
实际数据列全部不同时才为橙色冲突；新 ID 仍是新增，部分字段变化仍是普通修改。

共同基线仅用于分别比较 `BASE↔LOCAL` 和 `BASE↔REMOTE` 的核心表格语义，并生成
固定的合并说明，不参与覆盖值或保存目标选择。界面明确区分 Git 对二进制 XLSX
给出的“文件级冲突”和橙色语义冲突行：只有左右两侧都改变同一对齐记录且满足
既有冲突规则时才显示橙色；若一侧与基线语义一致，则说明没有双方语义冲突。

前端 `.content` 保持四条纵向布局轨道：来源卡、摘要区、双表格弹性区和底部差异
详情。对比结果与 Git 合并语义说明共同封装在 `comparison-summary-stack` 中，只占用
一条自动高度的摘要轨道；双表格是唯一的 `minmax(0, 1fr)` 弹性轨道。新增摘要类
提示不得作为 `.content` 的独立子节点，否则会把双表格挤入固定高度的详情轨道。

选中态和差异态可叠加：无差异选中项使用蓝色；四类差异保留原底色并叠加蓝色
边框。Summary 按工作表返回四类行计数，摘要区只读取当前选中工作表的单元格差异数
和四类行计数；Differences 和 Region 返回对应行状态，
所以“工作表与差异”、差异索引和网格使用同一后端分类。差异索引的四个导航
页签按单元格索引计数，默认顺序为冲突、修改、删除、增加；上一处/下一处只在
当前索引分类内循环。摘要区的增加、删除、修改、冲突是独立的多选行筛选：默认
全不选并显示完整表格，选中后只显示对应语义行。点击左侧索引分类会把行筛选同步
切为该分类；数字键 `1`–`4` 切换四类，`5` 在全选四类和全部不选之间切换。

## 前后端 API

Wails 暴露的 `Controller` 方法如下：

- `Bootstrap`、`SelectAndOpen`、`OpenFiles`：启动和文件选择。
- `LanguagePreference`、`SetLanguagePreference`、`SetRuntimeLocale`：设置窗口的语言读取、
  持久化和当前运行时切换。
- `ClearDifferenceIndexCache`、`ClearAllData`：只清除差异索引缓存，或清除全部已保存
  应用数据；均不修改当前工作簿、仓库和 Git 状态。
- `SelectRepository`、`OpenRepository`、`Repository`：打开和读取仓库状态。
- `SelectRepositoryFile`、`SelectRepositoryRef`：加载工作区文件并替换右侧引用。
- `RefreshRepository`、`SetRepositorySidebarWidth`：重新扫描和持久化目录树宽度。
- `Summary`：工作簿、工作表、未保存状态和撤销数量摘要。
- `SetRowAlignment`：在无撤销历史时切换安全主键对齐和严格物理行号比较。
- `SetKeyColumn`：在无撤销历史时为指定工作表设置列号主键，列号 `0` 表示显式取消。
- `Region`：读取指定工作表的局部矩形区域，同时返回左侧当前值和打开时快照值。
- `FilteredRegion`：按多选行分类读取压缩后的局部视口，并保留左右真实物理行映射。
- `Find`：在当前工作表指定侧和当前行筛选范围中建立或复用搜索缓存，只返回摘要。
- `NavigateFind`、`ClearFind`：O(1) 循环导航指定侧缓存，或只清除指定侧搜索与高亮。
- `Differences`：分页读取工作表差异索引，单次最多 10,000 条。
- `CopyRightToLeft`、`CopyRightToLeftMany`：单格和批量复制。
- `CopyRowsRightToLeft`：把所选右侧完整行覆盖到左侧相同行。
- `AppendRowsRightToLeft`：把所选右侧完整行追加到左侧；有 `id` 列时使用自动或
  逐行指定 ID，没有 `id` 列时原样追加到左侧数据末尾。
- `EditLeft`：文本、数字、公式和清空编辑。
- `ClearLeftSelection`：按矩形或筛选行映射批量清空可编辑左侧内容，并合并为一个撤销步骤。
- `Undo`：撤销最近一次单格、批量或编辑命令。
- `Save`、`SaveAs`：保存当前目标或打开原生另存为对话框；仓库模式的
  `SaveAs` 通过 `Session.Export` 导出副本，不改变工作区目标与 dirty 状态。

前端右键菜单先按后端返回的行分类筛选选区：未改动单元格/行不阻断菜单，但不会
进入批量坐标/行参数；冲突与非冲突差异同时存在时不调用上述写 API，而是提示用户
单独选择冲突部分。纯冲突选区仍进入覆盖/追加语义，非冲突选区进入复制语义；
`Session.AppendRowsRightToLeft` 也会再次校验每个来源行确为冲突，防止绕过界面追加
增加、删除或修改行。工具栏复制按钮同样只从当前后端差异索引提取选区坐标；相等
单格不会作为回退目标，按钮保留布局位置并显示 0、保持禁用。普通 Region 与
FilteredRegion 都把显示行映射回同一来源行后执行这一筛选。

## 合并与撤销

复制前后都通过 `merge.Capture` 捕获单元格值、公式、样式、超链接和批注。批量
复制和整行操作会去重坐标，单次最多 10,000 个；其中任一步失败时会倒序回滚
已应用项目，并包含可能已部分写入的当前单元格。来源填充样式编号超出 excelize
支持的 0–18 范围时只忽略该单元格填充并记录警告，值、公式和后续操作继续完成。
普通单格与批量 cell-copy 会在捕获和应用前按 `present + raw + formula + type` 过滤
相等坐标；全部相等时在应用、行重分类和历史记录前返回，部分相等时只把真实差异
作为一个撤销条目。`copy-row` 不使用该过滤，继续完整复制值、公式、样式、超链接和
批注。一次有效批量、整行覆盖或多行追加形成一个撤销条目。

只有 `id` 列在左右现有非空数据中全部可解析为整数时，才开放 ID 追加。自动追加
从左侧最大整数 ID 加一开始，多行按选择顺序连续分配；指定 ID 弹窗为每个来源行
提供一个输入框，并拒绝空值、批内重复或左侧已有 ID。若首行虽然名为 `id`，但
下面实际存放属性名等非整数数据，纯冲突选区只显示“将整行新增到左侧”，并把来源
整行原样追加到左侧当前最大数据行之后；增加、删除和修改行不显示整行新增操作。
复制、覆盖、追加、编辑和撤销完成后只重算
受影响工作表的稀疏行分类，不重新读取整个工作簿。

语义差异与“用户如何处理冲突”是两类状态。`Session` 另存
`RowResolution`：单元格覆盖、整行覆盖、非整数 ID 冲突行末尾追加、自动 ID 追加或指定 ID 追加。Summary
把仍有效的处理标记发给前端；右侧来源行显示处理方式，追加目标行在左侧强制
使用新增色，避免被纯物理行坐标对比显示为删除。处理标记绑定产生它的会话状态
编号，撤销对应操作时一并删除；替换或卸载右侧来源时清空，避免跨分支误标。

撤销条目保存 `BeforeState` 和 `AfterState`。每次修改生成新的状态编号，保存只更新 `savedState`，不会清空历史。因此保存后仍可逐步撤销；撤销到与最近保存不同的状态后，会话重新显示“有未保存修改”，用户再次保存才能把撤销结果写回磁盘。当前没有重做。
语义 no-op 不创建撤销条目或新状态编号，因此既不会把 clean 会话改成 dirty，也不会
清除会话中更早的未保存修改。

## 保存一致性

默认目标始终是加载时的左侧路径（除非给出 `--output` 或在直接文件模式使用
“另存为”）。直接文件模式另存成功后，会话目标切换到新文件，之后“保存左侧”
继续写该新目标；仓库模式则通过同一安全写入器导出副本，不切换 Session 目标、
不清除 dirty，也不改变仓库文件。外部修改检查使用
`size + mtime(ns) + SHA-256`。前端在窗口可见时定时检查，并在重新获得焦点后补查：
右侧与其他只读来源检测到变化后提示并自动重载；可编辑左侧显示确认弹窗，明确说明
重载会放弃 SheetProof 中尚未保存的修改，用户选择暂不重载时保留持续警告。实际重载
仍由 `Session` 重新打开工作簿并重建摘要、差异、历史与仓库状态，避免前端自行拼接状态。
临时文件与目标位于同一目录，因此最终 rename
不跨文件系统。任何写入或校验失败都会删除临时文件，原目标保持不变。

另存为对话框默认沿用左侧工作簿文件名。首次使用从平台下载目录开始；Windows 使用 Known Folder API，macOS 使用当前用户的 `Downloads`。仅在工作簿安全保存成功后，才把目标父目录写入系统用户配置目录的 `SheetProof/preferences.json`，后续会话优先从该目录开始。若新路径不存在而旧 `ugxlsx/preferences.json` 存在，首次读取会把完整偏好复制到新路径并保留旧文件作为回退；以后只写新路径。

安全保存顺序：

1. 校验扩展名、目标目录和写权限。
2. 保存当前目标时比较加载后的文件身份，阻止覆盖外部修改。
3. 在目标同目录创建 `.sheetproof-*.xlsx` 临时文件。
4. 写入、`fsync`、关闭并用 excelize 打开临时文件校验。
5. 再次检查目标身份，避免保存期间发生竞争修改。
6. 保留原权限并原子替换：Unix 使用同目录 rename，Windows 使用 `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`。
7. 同步目录，重新计算身份并再次打开最终文件。

仓库模式把 `Output` 清空，保存目标固定为当前工作区中的所选相对路径。
保存后重新读取 Git 状态以更新 modified 标记，但不会暂存、提交或清理
Git 工作区。merge、rebase、cherry-pick 等操作进行中时，保存前由控制器
显示警告。

## Git 安全边界

所有 Git 子进程都使用 `exec.CommandContext` 参数数组、明确的
`git -C <root>` 和 15 秒超时。文件路径先规范化为仓库内 `.xlsx` 相对路径；
引用必须来自 `for-each-ref` 返回的候选集合。分支下拉框和内部状态保留完整
引用，避免本地与远端同名时发生歧义。仓库功能不调用 shell，也不执行任何
写 Git 状态的命令。用户选中的完整引用按规范化仓库根目录保存在偏好文件中；
下次打开同一仓库时优先恢复。没有记录或记录已失效时先使用当前本地分支的
upstream；没有 upstream 时匹配 `origin/<当前分支>` 等同名远端引用，最后才
回退到当前排序后的第一候选。

## 保真边界

工具以原左侧 OOXML 包为基础做局部 excelize 修改，因此未触碰的常见工作表内容通常保持。回归测试覆盖样式、合并区域、行高、列宽、公式、超链接和批注。excelize 会重写 OOXML 包，未回归验证的高级对象不能承诺二进制或语义完全保真，详见 README 的已知限制。

## 仓库启动完成条件

仓库模式在扫描完成后可以先发布文件树和引用候选，但只要启动参数包含预选的
`.xlsx` 相对路径，`Controller.Bootstrap().Loading` 就必须持续为 `true`，直到该工作簿与
选定 Git 引用已经共同建立 `Session`。前端启动轮询以该标记作为完成条件；提前清除会使
轮询在 `HasSession=false` 时退出，留下无法自行恢复的空白工作区。无预选文件时，完成仓库
扫描后可以正常进入等待用户选择文件的仓库视图。
