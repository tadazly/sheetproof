# ugxlsx 架构

`ugxlsx` 将 Excel 处理保持在 Go 后端，GUI 与 CLI 复用相同领域逻辑。

## 数据流

1. `workbook.Reader` 用 excelize 打开 `.xlsx`，同时计算文件大小、mtime 和 SHA-256。
2. Reader 只遍历工作表的实际行和已存在单元格，形成稀疏 `WorkbookSnapshot`。
3. `diff.Compare` 对两个已经按行列排序的单元格序列做线性归并，复杂度为 O(L+R)。
4. GUI 首次只获取工作簿和工作表摘要；工作表差异分页获取，网格以视口区域获取。
5. 合并或编辑直接修改左侧的 excelize 工作簿对象，并把操作前后状态和会话状态编号压入撤销栈。
6. 保存时先核对左侧文件身份，再写同目录临时文件、`fsync`、重新打开校验、再次核对身份，最后原子替换。

## 包职责

- `internal/workbook`：文件校验、身份、稀疏快照和单元格模型。
- `internal/diff`：工作表集合、顺序和单元格差异。
- `internal/merge`：单元格内容、公式、样式、超链接、批注的捕获和应用。
- `internal/history`：会话级命令栈。
- `internal/storage`：安全保存与保存后验证。
- `internal/preferences`：跨会话保存“另存为”的最后目录。
- `internal/app`：并发安全的 GUI/CLI 共享会话。
- `internal/cli`：命令解析、结构化输出和退出码。
- `frontend`：Vue 3 双栏视口化网格。

## 并发和内存

首版快照加载按工作表顺序执行，以避免同时解压多个大型 worksheet XML 导致内存峰值失控。差异阶段不构造矩形空白区域；每个有效单元格只在稀疏 map 和排序键序列中出现。GUI 区域 API 最大返回 300×100，当前前端视口请求为 48×20。会话由读写锁保护，保存和编辑不会重入。

前端在滚动停止后按视口请求区域，不把整份工作簿序列化到 WebView。每个区域请求带有递增序号，较早请求即使晚返回也不会覆盖新区域；并发请求使用计数器维护忙碌状态。差异导航先把左右滚动容器设置到目标，再读取浏览器实际的 `scrollTop/scrollLeft`。这样靠近工作表底部或右侧时，即使浏览器限制了目标滚动值，列标题、行标题和虚拟区域仍使用同一实际坐标，不会发生表头漂移或大片空白。

启动时后端异步打开命令行传入的两个工作簿，前端轮询 `Bootstrap`。启动全过程显示居中的阻塞式加载提示，完成后才展示可操作状态。

## 前后端 API

Wails 暴露的 `Controller` 方法如下：

- `Bootstrap`、`SelectAndOpen`、`OpenFiles`：启动和文件选择。
- `Summary`：工作簿、工作表、未保存状态和撤销数量摘要。
- `Region`：读取指定工作表的局部矩形区域。
- `Differences`：分页读取工作表差异索引，单次最多 10,000 条。
- `CopyRightToLeft`、`CopyRightToLeftMany`：单格和批量复制。
- `EditLeft`：文本、数字、公式和清空编辑。
- `Undo`：撤销最近一次单格、批量或编辑命令。
- `Save`、`SaveAs`：保存当前目标或打开原生另存为对话框。

## 合并与撤销

复制前后都通过 `merge.Capture` 捕获单元格值、公式、样式、超链接和批注。批量复制会去重坐标，单次最多 10,000 个；其中任一步失败时会倒序回滚已应用项目。一次批量复制形成一个撤销条目，多次独立复制形成多个条目。

撤销条目保存 `BeforeState` 和 `AfterState`。每次修改生成新的状态编号，保存只更新 `savedState`，不会清空历史。因此保存后仍可逐步撤销；撤销到与最近保存不同的状态后，会话重新显示“有未保存修改”，用户再次保存才能把撤销结果写回磁盘。当前没有重做。

## 保存一致性

默认目标始终是加载时的左侧路径（除非给出 `--output` 或使用“另存为”）。另存为成功后，会话目标切换到新文件，之后“保存左侧”继续写该新目标。外部修改检查使用 `size + mtime(ns) + SHA-256`。临时文件与目标位于同一目录，因此最终 rename 不跨文件系统。任何写入或校验失败都会删除临时文件，原目标保持不变。

另存为对话框默认沿用左侧工作簿文件名。首次使用从平台下载目录开始；Windows 使用 Known Folder API，macOS 使用当前用户的 `Downloads`。仅在工作簿安全保存成功后，才把目标父目录写入系统用户配置目录的 `ugxlsx/preferences.json`，后续会话优先从该目录开始。

安全保存顺序：

1. 校验扩展名、目标目录和写权限。
2. 保存当前目标时比较加载后的文件身份，阻止覆盖外部修改。
3. 在目标同目录创建 `.ugxlsx-*.xlsx` 临时文件。
4. 写入、`fsync`、关闭并用 excelize 打开临时文件校验。
5. 再次检查目标身份，避免保存期间发生竞争修改。
6. 保留原权限并原子替换：Unix 使用同目录 rename，Windows 使用 `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`。
7. 同步目录，重新计算身份并再次打开最终文件。

## 保真边界

工具以原左侧 OOXML 包为基础做局部 excelize 修改，因此未触碰的常见工作表内容通常保持。回归测试覆盖样式、合并区域、行高、列宽、公式、超链接和批注。excelize 会重写 OOXML 包，未回归验证的高级对象不能承诺二进制或语义完全保真，详见 README 的已知限制。
